# C Insight 0.22.23

## 中文

### 宏调用者查询补全

- 修复数值宏、表达式宏以及其他宏的替换文本中使用的宏没有调用者结果的问题。宏识别不再要求分析提供程序先返回函数调用层次根节点；例如 `AVERROR_EOF`、`AVERROR` 和 `EAGAIN` 可以根据宏自身的引用生成结果。
- 保留之前的查询范围：默认只显示所选宏自身的直接引用，不会静默切换到展开后函数的全部调用者。对于 `#define MY_PRINTF_2 MY_PRINTF`，查询右侧的 `MY_PRINTF` 显示这一行对它的引用；查询 `MY_PRINTF_2` 则显示实际拼写为 `MY_PRINTF_2` 的使用位置。
- 宏定义名、普通使用位置和另一个宏的替换文本均可作为入口；只用于宏展示的合成根不会进入被调用者查询。

### 跨文件可靠性与资源占用

- 修复跨文件宏查询可能出现的 `trying to get AST for non-added document`。未打开文件中的引用会保留准确的可导航位置，不再直接向 clangd 请求该文件尚不存在的 AST。
- 已打开文件继续尽可能解析引用所属函数；未解析的位置使用通用“宏引用”标签，而不是误称为函数之外的引用。单个文件的符号查询失败不会再中断整个宏查询；取消操作仍会正常取消，不会缓存为部分成功。
- 不会仅为了显示所属函数标签而批量打开引用文件、构建 AST。打开相关源码并刷新后，如果提供程序能够返回函数符号，该位置可以进一步显示为所属函数。
- 宏识别复用光标查询已有的定义请求，避免重复语义请求；普通同名函数保留已有快速路径。

### 展开后函数入口与兼容性

- 标题栏和右键菜单中的“查询宏展开后函数的调用者”仍需手动执行。已有可调用目标时复用原始提供程序项；否则只在该操作中按需同步并尝试最多 16 个实际宏使用位置。
- 常量等非函数目标不会被误当作展开后函数；无法解析目标时保留现有宏结果并提示。刷新或重新查询调用者恢复默认宏引用范围。
- 本版不新增配置项。宏结果仍取决于活动编译配置、索引和提供程序返回的引用；未激活分支或确实未使用的宏可能合理地没有结果。

### 文档与验证

- 中英文 README、用户手册、交叉编译指南、架构、开发者手册、路线图与文档索引已同步为 `0.22.23`；历史发布记录和带日期的实测数据不改写。
- 完整质量门、281 项测试（68 个测试套件）及真实 VS Code + clangd Extension Host 冒烟测试通过，覆盖宏别名、数值/表达式宏、头文件定义、缺少 AST、取消、缓存，以及默认与手动展开后的查询范围。
- 慢速输入冒烟测试在每次原生输入前立即恢复编辑器焦点，避免异步等待期间 Webview 的迟到聚焦导致字符未进入夹具；文本、查询数量和编辑门控断言保持不变，并补充失败定位信息。
- 已在 FFmpeg 的指定 `MY_PRINTF`、`MY_PRINTF_2`、`AVERROR_EOF`、`AVERROR`、`EAGAIN` 和 `config.h` 位置完成只读模拟查询，且临时 VSIX 已通过用户验收。自动探测关闭了后台索引，不把观测结果数量或耗时作为全工程完整性和性能承诺。

## English

### Broader macro Callers coverage

- Fixed missing Callers results for numeric/expression macros and macro tokens used in another macro's replacement text. Identification no longer requires the Provider to prepare a callable root first; macros such as `AVERROR_EOF`, `AVERROR`, and `EAGAIN` can produce results from their own References.
- Preserved the existing scope: the default query contains direct references to the selected macro, not every caller of its expanded function. In `#define MY_PRINTF_2 MY_PRINTF`, selecting the right-hand `MY_PRINTF` returns that direct replacement-text reference; selecting `MY_PRINTF_2` returns uses spelled `MY_PRINTF_2`.
- Definition names, normal uses, and replacement-list references are supported entry points. Synthetic macro-only roots never enter Callees.

### Cross-file reliability and resource use

- Fixed cross-file macro queries failing with `trying to get AST for non-added document`. References in unopened files retain exact navigable positions instead of requesting an AST clangd does not have.
- Available open-document symbols still identify enclosing functions. Unresolved positions use a generic macro-reference label rather than claiming they occur outside a function. Per-file symbol failures no longer abort the entire macro query; cancellation still propagates instead of being cached as partial success.
- Reference files are not bulk-opened or parsed merely to obtain function labels. Opening the relevant source and refreshing can resolve the enclosing function when the Provider supplies it.
- Macro identification shares the cursor's existing Definition promise, avoiding duplicate semantic requests; ordinary matching native functions retain their fast path.

### Explicit expanded-function action and compatibility

- **Show Expanded Function Callers** remains an explicit title-bar or context-menu action. It reuses a retained callable Provider item, or synchronizes and examines at most 16 actual macro uses only when invoked.
- Constants and other non-callable targets are not accepted as expanded functions. Unresolved targets keep the current macro result and show an explanation. Refreshing or querying Callers again restores direct-macro scope.
- No new setting is introduced. Macro results still depend on the active compilation configuration, indexing, and Provider reference coverage; inactive branches and unused macros may legitimately have no results.

### Documentation and validation

- The bilingual READMEs, user guides, cross-compilation guides, architecture, developer guide, roadmap, and documentation index now use the `0.22.23` baseline. Historical release records and dated measurements remain unchanged.
- The complete quality gate, 281 tests across 68 suites, and real VS Code + clangd Extension Host smoke testing passed, including aliases, numeric/expression macros, header definitions, missing ASTs, cancellation, caching, and default-versus-explicit expanded-target scope.
- The slow-typing smoke test restores editor focus immediately before each native input, preventing late Webview focus during asynchronous waits from swallowing fixture input. Exact text, query-count, and edit-gate assertions remain unchanged, with richer failure diagnostics.
- Read-only simulated queries covered the specified FFmpeg `MY_PRINTF`, `MY_PRINTF_2`, `AVERROR_EOF`, `AVERROR`, `EAGAIN`, and `config.h` locations, and the user accepted the temporary VSIX. The automated probe disabled background indexing, so observed counts and timings are not whole-workspace completeness or performance guarantees.

## 安装与校验 / Installation and verification

从 [GitHub Release](https://github.com/H9elix/c-insight/releases/tag/v0.22.23) 下载 `c-insight-0.22.23.vsix` 与 `SHA256SUMS`，在同一目录中执行 `sha256sum -c SHA256SUMS`，然后在 VS Code 中运行 **扩展：从 VSIX 安装...**。完整调用层次建议使用 clangd 20 或更高版本；Microsoft C/C++ 语言服务仍为明确选择后启用的可选引擎。

Download `c-insight-0.22.23.vsix` and `SHA256SUMS` from the [GitHub Release](https://github.com/H9elix/c-insight/releases/tag/v0.22.23), run `sha256sum -c SHA256SUMS` in the same directory, and use **Extensions: Install from VSIX...** in VS Code. clangd 20 or newer is recommended for complete Call Hierarchy support; the Microsoft C/C++ language service remains an explicitly selected optional engine.
