# C Insight 0.23.4

## 中文

### 0.23 版本新增功能

- 新增组合视图，可将代码预览、调用者、引用等功能放到同一个视图中，最多保存四个命名组合，支持水平或垂直排列，原有独立视图仍可使用。
- 支持拖动子栏目标题排序、拖动分隔条调整尺寸及折叠窗格，整套内部布局可跨工程复用；同一功能共享查询结果和固定状态，树窗格保留各自的筛选、展开和滚动位置。
- 鼠标悬停时平滑扩大当前阅读区域，移出组合后恢复比例；支持单向或双向扩展及可配置的触发、动画和恢复时间，标题与按钮操作区保持位置稳定。组合内的滚动条、界面和代码字体随 VS Code 主题及字体设置更新。

### 0.23.2 更新

- 新增“C Insight：打开视图…”统一入口，可按名称或用途搜索全部 15 个独立视图，打开已有组合视图，或创建、管理组合。
- 首次显示 C Insight 栏目时提供一次性提示，帮助找到其他视图入口；后续打开不重复提示。
- 整理 C/C++ 编辑器右键菜单：C Insight 入口位于 clangd 的“Switch Between Source/Header”下方，以分隔线独立成组；“打开视图”和“添加书签”排在前面，包含关系与关系图保留在顶层，定义、引用、调用及类型查询收纳到“符号导航”子菜单。

### 0.23.3 更新

- 为组合视图的每个子栏目新增独立的悬停展开目标占比。可在子栏目菜单中设置 `1–100%` 或恢复默认，配置随栏目排序保留；未设置时沿用原有加权展开效果，并继续遵守扩展方向和相邻栏目的最小尺寸。
- 修复文档符号、工程文件在展开后上下滚动，再缩回时高亮项未恢复可见的问题。连续多轮操作均会在缩回后检查目标；不可见时居中，仍可见时保持原滚动位置，展开浏览期间不会拉回。
- 缩回后的居中定位改为可打断的平滑滚动。滚轮、搜索、锁定或显式导航会停止旧动画，启用系统或 VS Code 的减少动态效果时直接定位；筛选、树展开及其他显示实例保持不变。

### 0.23.4 更新

- 组合视图支持各子栏目独立设置双向、向右／向下、向左／向上三种扩展方向，并提供恢复默认；方向入口集中在子栏目的“…”菜单，总方向按钮和统一方向菜单移除。
- 未配置方向时，当前未折叠的最右／最下栏目默认双向，其余向右／向下。排序、折叠或增删栏目后自动更新默认，显式方向随栏目身份保留，不影响其他组合。
- 向左／向上扩展固定右／下边界，向右／向下固定左／上边界；只借指定侧余量，并继续遵守展开占比、最小尺寸及按钮保护。旧布局保留原方向，仅读取不写设置，下次用户修改布局时转换为逐栏配置。

## English

### New in 0.23

- Added combined views that place Code Preview, Callers, References and other features together. Save up to four named horizontal or vertical combinations while retaining the original independent views.
- Reorder panes by dragging their titles, resize them with splitters, collapse panes and reuse the internal layout across projects. Feature results and pins are shared, while tree panes retain their own filtering, expansion and scrolling.
- Smoothly enlarge the reading pane on hover and restore proportions when leaving the combination. Choose forward or both-direction expansion and configure dwell, animation and restoration timing; protected titles and controls keep click targets stable. Embedded scrollbars, UI typography and code fonts follow VS Code theme and font settings.

### 0.23.2 updates

- Added **C Insight: Open View…**, a searchable entry point for all fifteen independent views, existing combined views, and combination creation and management. Search by view name or purpose.
- Added a one-time tip when a C Insight pane first becomes visible, helping new users discover other views without repeating the notification on later opens.
- Organized the C/C++ editor context menu into a separate group below clangd's **Switch Between Source/Header**, with a native separator. **Open View** and bookmarks come first, include and graph actions remain at the top level, and explicit definition, reference, call and type queries are grouped under **Symbol Navigation**.

### 0.23.3 updates

- Added an independent hover expansion target percentage for each combined-view pane. Set `1–100%` or restore the default from its pane menu; targets stay with panes when reordered. Unset panes retain weighted expansion, and direction and neighboring minimum-size limits still apply.
- Fixed Document Symbols and Project Files losing their followed highlight after wheel browsing in an expanded pane and then contracting it. Repeated cycles now restore out-of-view targets while leaving visible rows in place and keeping expanded browsing uninterrupted.
- Centering after contraction now uses interruptible smooth scrolling. Wheel input, search, locking or explicit navigation stops the previous animation; system or VS Code reduced-motion preferences use immediate positioning. Filters, tree expansion and other presentation instances stay unchanged.

### 0.23.4 updates

- Combined views now support independent both, right/down and left/up hover expansion for each pane, with a reset to default. Direction controls are available only in each pane's **…** menu; the combination-wide direction button and menu have been removed.
- Unconfigured panes follow expanded order: the rightmost/bottommost expanded pane defaults to both directions, while others expand right/down. Defaults update after reordering, collapsing, adding or removing panes; explicit choices stay with pane identity and do not affect other combinations.
- Left/up expansion fixes the trailing edge, and right/down expansion fixes the leading edge. One-way modes borrow only the permitted side's slack while respecting target percentages, minimum sizes and control protection. Legacy layouts retain their directions, with no settings writes on read; the next user layout edit saves per-pane choices.
