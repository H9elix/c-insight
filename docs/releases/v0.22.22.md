# C Insight 0.22.22

## 中文

### 导航与展开相互独立

- 上下文（Context）、引用（References）、调用者（Callers）、被调用者（Callees）、父类型/子类型、包含文件/被包含关系、导航历史、书签、文档符号和工程诊断共 12 个原生结果树统一改用 Webview 自绘树。代码预览、符号搜索和关系图保留原有 Webview 实现。
- 单击源码位置名称立即更新代码预览；在 `cInsight.navigation.doubleClickInterval` 时间内再次单击同一名称，在编辑器打开同一位置。双击不会再附带展开或折叠动作，已展开和未展开的节点均保持原状态。
- 左侧箭头独立负责展开/折叠；无源码位置的普通分组名称不触发导航，刷新、加载更多等操作节点继续执行各自命令。
- 双击或 Enter 打开后继续保留原有随光标抑制：上下文、代码预览、引用和调用层次不会立即跟随跳转落点刷新，主动移动编辑器光标后才恢复。文档符号和工程诊断仍独立跟随活动文件。

### 键盘、筛选与性能

- 上下方向键及 Home/End 移动选择并预览，左右方向键控制分支，Enter 打开，空格预览；右键或 Shift+F10 显示节点对应的操作菜单。
- 结果内容区顶部提供全部折叠和本地筛选图标。Ctrl+F/Cmd+F 打开筛选，Escape 清空并关闭；筛选范围是当前已展开的结果，不会隐式查询未展开分支。
- 虚拟滚动只绘制可见区域附近的行，源码描述也只为该区域按需补充。隐藏窗口不因 UI 重绘而查询，折叠分支仍采用懒加载；并发子项加载会合并，过期异步结果不会覆盖新树。
- 保留原有引擎查询路径、固定状态、按深度展开、搜索定位和调用树会话恢复。本版不新增配置项，也不改变 clangd 与 Microsoft C/C++ 的语义分析范围。

### 布局、外观与文档

- 视图 ID、C Insight 容器以及外层标题栏仍由 VS Code 管理。调用者和被调用者可以共同放在底部同一个 C Insight 标签内；拖放难以命中时，可运行“视图: 移动视图”，选择已有目标容器，而不是新建面板。
- 图标使用官方 Codicons，颜色跟随 VS Code 颜色主题；产品图标主题替换的自定义字形不会自动映射到 Webview。
- 中英文 README、用户手册、交叉编译指南、开发者手册、架构、路线图和文档索引已同步为 `0.22.22`，并补充自绘结果树维护边界与布局操作。历史发布记录及带日期的实测数据保持原样。

### 验证

- 完整质量门、277 项测试（67 个测试套件）和真实 VS Code + clangd Extension Host 冒烟测试通过。
- 自动化覆盖双击与展开动作分离、懒加载竞态、旧结果丢弃、重复节点名称、消息边界、虚拟滚动，以及真实调用者/被调用者的预览和跳转路径。
- 慢速输入冒烟测试显式恢复编辑器焦点，并验证字符确实写入夹具后才检查查询抑制，避免 Webview 焦点竞态造成误报；原有查询数量和编辑门控断言保持不变。
- 用户已完成试验临时包和合并后主干临时包的人工测试；鼠标手感、布局、主题与辅助技术表现仍需在各自实际环境中持续回归。

## English

### Navigation independent from expansion

- Replaced 12 native result trees with one shared Webview renderer: Context, References, Callers, Callees, Supertypes/Subtypes, Includes/Included By, Navigation History, Bookmarks, Document Symbols, and Project Diagnostics. Code Preview, Symbol Search, and Relationship Graph retain their existing Webview implementations.
- Clicking a source-location name previews it immediately. Clicking the same name again within `cInsight.navigation.doubleClickInterval` opens that exact location in the editor without expanding or collapsing the branch, regardless of its current state.
- Disclosure arrows control expansion independently. Ordinary groups without source locations do not navigate; action rows such as Refresh and Load More keep their own commands.
- Double-click and Enter navigation retain cursor-follow suppression: Context, Code Preview, References, and Call Hierarchy do not immediately follow the programmatic editor target. Deliberate editor cursor movement resumes following, while Document Symbols and Project Diagnostics retain their independent active-document behavior.

### Keyboard, filtering, and performance

- Up/Down and Home/End select and preview; Left/Right navigate branches; Enter opens and Space previews. Right-click or Shift+F10 opens the applicable node menu.
- Each result view provides Collapse All and a local filter. Ctrl+F/Cmd+F opens the filter and Escape clears and closes it. Filtering covers currently expanded results without querying unopened branches.
- Virtual scrolling renders only rows near the viewport, and source descriptions are resolved on demand for that area. Hidden views do not query merely for UI rendering, collapsed branches stay lazy, concurrent child loads are coalesced, and obsolete asynchronous results cannot replace the newer tree.
- Existing engine query paths, pinning, depth expansion, search reveal, and Call Hierarchy sessions are retained. No new setting or change to clangd/Microsoft C/C++ semantic-analysis scope is introduced.

### Layout, appearance, and documentation

- View IDs, the C Insight container, and outer headers remain managed by VS Code. Callers and Callees can share one C Insight tab in the bottom panel. When drag targets are difficult to reach, use View: Move View and choose the existing destination container rather than a new panel.
- Official Codicons follow VS Code color themes; custom glyph replacements from product icon themes are not automatically mapped into the Webview.
- The bilingual READMEs, user guides, cross-compilation guides, developer guide, architecture, roadmap, and documentation index now use the `0.22.22` baseline, including result-tree ownership and layout guidance. Historical release records and dated measurements remain unchanged.

### Validation

- The complete quality gate, 277 tests across 67 suites, and real VS Code + clangd Extension Host smoke testing passed.
- Automation covers independent double-click/expansion behavior, lazy-loading races, stale results, duplicate labels, message boundaries, virtualization, and real Caller/Callee preview and editor-navigation paths.
- The slow-typing smoke probe explicitly restores editor focus and verifies actual fixture text before checking suppression, avoiding a Webview-focus race without relaxing the existing query-count or edit-gate assertions.
- The user completed manual testing of both the experimental preview and merged-main preview packages. Pointer interaction, layout, themes, and assistive technologies continue to require regression checks in their actual environments.

## 安装与校验 / Installation and verification

从 [GitHub Release](https://github.com/H9elix/c-insight/releases/tag/v0.22.22) 下载 `c-insight-0.22.22.vsix` 与 `SHA256SUMS`，校验后在 VS Code 中运行 **扩展：从 VSIX 安装...**。在同一目录中可以执行 `sha256sum -c SHA256SUMS`。完整调用层次建议使用 clangd 20 或更高版本；Microsoft C/C++ 语言服务仍为明确选择后启用的可选引擎。

Download `c-insight-0.22.22.vsix` and `SHA256SUMS` from the [GitHub Release](https://github.com/H9elix/c-insight/releases/tag/v0.22.22), verify them with `sha256sum -c SHA256SUMS` in the same directory, and run **Extensions: Install from VSIX...** in VS Code. clangd 20 or newer is recommended for complete Call Hierarchy support; the Microsoft C/C++ language service remains an explicitly selected optional engine.
