# 自绘结果树交互与维护

本文说明共享 Webview 结果树的交互、布局和维护职责。安装与配置见[用户手册](../user/user-guide.zh-CN.md#1-运行要求)。

## 范围与操作

上下文（Context）、引用（References）、调用者（Callers）、被调用者（Callees）、父类型（Supertypes）、子类型（Subtypes）、包含文件（Includes）、被包含关系（Included By）、导航历史（Navigation History）、书签（Bookmarks）、文档符号（Document Symbols）及工程诊断（Project Diagnostics）共用自绘树。符号搜索和代码预览已有独立 Webview，保持各自布局。

| 操作 | 行为 |
| --- | --- |
| 单击源码位置节点名称 | 立即更新代码预览，保持树展开状态 |
| 在配置的双击间隔内再次单击同一名称 | 在编辑器打开同一位置，保持树展开状态 |
| 单击左侧箭头 | 只展开或折叠；展开未加载分支时才查询其子项 |
| 上下方向键、Home、End | 移动选择并预览有源码位置的结果 |
| 右方向键 | 展开当前节点，或进入已展开节点的第一个子项 |
| 左方向键 | 折叠当前节点，或返回父项 |
| Enter / 空格 | 在编辑器打开 / 在代码预览显示 |
| 右键 / Shift+F10 | 显示节点对应的打开、复制引用、书签或宏展开查询菜单 |
| 视图内容顶部的全部折叠图标 | 折叠该窗口的所有分支 |
| 筛选图标 / Ctrl+F / Cmd+F | 筛选当前已展开树中的名称和描述；Escape 清空并关闭 |

文档符号和工程文件使用顶部常驻搜索框，Escape 只清空。文档符号按名称子串筛选全部已加载符号，包含折叠成员并保留父链；筛选中的箭头和全部折叠只影响当前匹配投影，清空后回到正常树。工程文件按名称/路径筛选平铺清单，并保留其独立焦点、自动跟随和锁定策略。

没有源码位置的普通分组名称不会触发导航；其展开仍使用箭头。刷新、加载更多等操作节点执行自身命令。双击/Enter 打开源码后暂停光标自动刷新，直到主动移动编辑器光标才恢复。

## 布局与分组

结果树的内容区域由 Webview 绘制；外层标题栏、标题栏命令、视图容器和布局移动由 VS Code 管理，容器 ID 为 `cInsight`。代码预览（Code Preview）、符号搜索（Symbol Search）和关系图（Relationship Graph）使用各自独立的 Webview 实现。

调用者（Callers）和被调用者（Callees）仍可放在底部面板同一个 C Insight 标签内。鼠标拖放未命中目标时，可在命令面板运行 **视图: 移动视图（View: Move View）**，选择要移动的视图，再选择已有的目标容器；不要选择新建面板，否则会创建独立标签。也可使用 **视图: 移动焦点视图（View: Move Focused View）**。不需要重置全部视图布局。

## 维护边界

组合视图（Combined View）在一个原生 Webview 里复用受控 `srcdoc` 子窗格，不修改 VS Code 工作台 DOM 或布局数据库。`combined/combinedViewManager.ts` 管理四个静态槽位、全局配置、菜单白名单、代次校验及显示实例生命周期；`combinedModel.ts` 管理配置归一化、功能目录、菜单条件与最小尺寸分配；`embeddedView.ts` 将现有显示提供程序接入子窗格；`combinedWebview.ts` 管理消息桥、主题变量、局部 Webview 状态、悬停与分隔条。子窗格只接收本扩展生成的转义 HTML，使用父级 CSP nonce；父级按窗口来源和代次路由消息，不能从网页指定任意 VS Code 命令。官方 Codicons 资源由组合窗口读取一次，CSS 内联到子文档、字体经窗口级 Blob URL 复用，避开 VS Code 本地资源代理对子文档的限制；关闭组合文档时撤销 Blob URL。

组合总工具栏按排列方向显示为左侧竖栏或顶部横栏，子窗格标题保持原布局。悬停触发、动画及移出恢复时长为用户级热更新配置；它们不改变功能可见性、查询控制器或子文档代次。验证入口与人工重点见[组合视图验证](../validation/combined-views.zh-CN.md)。

原有功能控制器继续拥有查询、结果和固定/锁定状态。多个树显示实例共享提供程序的子项加载合并，但有独立树模型及跟随控制器；有效可见性按所有实例取或，只在有效值变化时通知查询控制器。预览共享目标、所有权、取消代次和令牌缓存，独立保存加载范围及滚动状态。窗口比例、方向和悬停不销毁子文档；隐藏组合不发布 UI 更新，移除窗格会释放对应实例和监听器。

- `resultTreeModel.ts`：不依赖 VS Code 的展开状态、稳定行 ID、懒加载投影、定位和过时代次丢弃。
- `resultTreeView.ts`：将现有 `MutableTreeProvider` 接到 Webview，校验消息及节点菜单动作，桥接展开事件、可见性与源码导航。
- `resultTreeWebview.ts`：独立点击处理、虚拟滚动、键盘导航、ARIA 树角色、上下文菜单及本地筛选；动态文本仅通过 DOM 文本属性输出。
- `viewLifecycle.ts`：统一注册和释放上述视图，视图 ID 及原有标题栏命令保持一致。
- `utils/editorNavigation.ts`：打开编辑器时直接指定目标光标；结果树、代码预览、显式打开和关系图共用该路径，由 VS Code 管理原生导航历史。
- `treeNode.ts`：保留业务节点并合并同一节点的并发子项加载，防止程序化展开与 UI 刷新重复查询。
- `scripts/copy-webview-assets.mjs`：在构建时复制官方 Codicons 的 CSS 与字体到 `dist/codicons`，通过 VSIX 文件清单打包；许可计入第三方声明。

隐藏窗口只记录数据变更，不启动 UI 刷新或因 UI 投影而读取源码片段。不为折叠分支触发语义加载；文档符号的额外筛选索引只遍历已在内存中的 `children`。只有虚拟滚动窗口内的节点才触发原有 `resolveVisible` 补充描述，避免大量结果产生后台源码读取。已有按深度展开、搜索定位和工作区调用树恢复通过统一 `reveal` 接口接入；双击导航本身不执行展开、折叠或补偿性恢复。

图标使用官方 Codicons 字体，符号颜色跟随 VS Code 颜色主题。原生树中由产品图标主题替换的自定义字形不会自动传入 Webview；当前实现优先保持标准图标与主题颜色一致。屏幕阅读器树角色和键盘路径已接入，但仍需实际辅助技术验收。

## 重点验证

1. 调用者与被调用者分别测试未展开节点和已展开节点：双击只跳转，树状态不变。
2. 单击名称只预览；单击箭头只展开/折叠；重复点击和快速切换节点时目标正确。
3. 测试类型、包含、引用分组、文档符号与书签分组，确认相同交互成立。
4. 测试右键菜单、按深度展开、搜索定位、全部折叠、引用分组自动展开配置和调用树会话恢复。
5. 测试键盘、明暗与高对比度主题、中文/英文、长行横向滚动及大量结果的滚动。
6. 固定调用树/引用后浏览其他符号，确认原结果保留；双击后不立即跟随落点刷新。
7. 折叠或隐藏窗口后修改/浏览源码，确认查询仍遵循原有按需规则。
8. 将调用者和被调用者移入底部同一个 C Insight 容器，确认可共同显示；重新加载窗口后检查布局和交互。
9. 先在目标文件较远的一行停留并关闭，再从另一文件双击结果跳入；鼠标侧键后退一次应回到跳转前位置，前进一次应回到目标，不停留于目标文件的旧光标。对已经打开的文件、同文件跳转和代码预览重复验证，既有合法历史不应丢失。
10. 在文档符号搜索折叠类/结构体中的成员，核对父链、无匹配提示、“×”及 Escape、独立筛选展开和清空恢复。未锁定时双击/Enter 成功打开后清空，单击预览保留；焦点在视图内或已锁定时不自动清空/滚动，离焦跟随只清空隐藏目标的查询。输入只本地过滤，不增加查询；同时回归工程文件的搜索、锁定和跟随。

自动测试执行浏览器事件处理脚本，检查双击与箭头分离、懒加载竞态、旧结果丢弃、重复名称、初始展开、定位和消息校验；Extension Host 使用真实 clangd 验证调用树预览、编辑器跳转和展开状态。人工回归检查鼠标手感、主题、布局拖放和屏幕阅读器。
