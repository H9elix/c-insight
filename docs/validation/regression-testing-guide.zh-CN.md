# C Insight 历史问题驱动测试指南

本指南基于当前 `0.23.4` 代码、已有测试、更新日志与历次用户反馈整理，首次汇编日期为 `2026-10-17`。具体缺陷、配置问题、行为约定和已知限制见[历史问题与回归案例库](historical-issues.zh-CN.md)，共 `56` 条记录。

本指南及案例库中的源码和测试链接面向 GitHub 或完整源码工作副本；从已安装扩展阅读时，请到项目仓库打开这些文件。

## 1. 如何使用

1. 收到问题先按现象查案例库，复用已有编号；新问题建立新编号，先标注待复现或待定位。
2. 修复前保存能复现旧行为的最小步骤和证据；修复后用同一场景验证，不只检查最终界面有结果。
3. 按下表选择定向测试，再执行与改动风险相称的完整检查。补充新的自动断言，不把手工点过一次当成自动覆盖。
4. 临时包交付时给出本次问题编号、已执行结果和人工重点；用户确认后才能记录用户验收，再按授权发布。
5. 以后收到新的实际问题时，同步更新案例库；影响共性规则或选择范围时也更新本指南。维护要求已写入[仓库规则](../../AGENTS.md)和[贡献指南](../../CONTRIBUTING.md)。

案例库按证据区分插件缺陷、外部引擎故障、配置问题和预期行为，保留未知项与已证伪假设。

## 2. 测试层级与通过条件

| 层级 | 适合发现的问题 | 需补充的验证 |
| --- | --- | --- |
| 纯模型单元测试 | 范围、分类、节点预算、去重、取消、缓存、历史和状态转换 | VS Code 真实事件、鼠标交互和外部进程 |
| 静态接线与文档契约 | 命令唯一注册、共享入口、配置默认值、语言目录、源码调用约束 | 运行时查询、显示效果和后台请求计数 |
| 真实 clangd 协议集成 | 初始化和支持的协议方法 | 目标版本、工具链和大型工程 |
| 隔离扩展宿主端到端测试（Extension Host E2E） | 编辑器事件、真实引擎、预览状态、树宿主动作、原生后退/前进 | 硬件滚轮/侧键、主题和目标 Remote 环境 |
| FFmpeg 或实际嵌入式工程 | 编译配置、跨文件行为、真实索引和请求数量 | 目标机器、冷暖索引及各平台编译配置 |
| 人工 UI 验收 | 滚动闪烁、布局、固定按钮、主题、侧键和操作连续性 | 环境记录、请求计数和自动回归断言 |

每次执行记录构建、环境、命令和结果；跳过、不可用、超时、外部引擎崩溃及待用户确认分别标记。

## 3. 环境与证据准备

- 记录扩展版本、临时包完整文件名或提交、VS Code 版本、分析引擎及版本、主题、Local/WSL/SSH/容器、单文件夹或多根工作区。
- 记录有效设置，而不只保存某一个 `settings.json`：用户、远程、工作区、文件夹及语言专属设置可能同时影响结果。
- 检查编译数据库是否有目标 `.c/.cpp` 条目，包含目录、宏、生成头文件、目标架构和 sysroot 是否真实有效；不要仅因其他文件能分析就认为当前文件配置正确。
- 小夹具用于确定语义及事件顺序；FFmpeg 用于观察跨文件和规模效应。使用符号名和源码片段定位，行号只作参考，不能假设不同 FFmpeg 修订中的第 37/41/42/134 行内容相同。
- 同时准备冷索引与暖索引场景；慢速输入、快速切换和多窗口可见是独立维度，不能只测试空闲状态。
- 采集 C Insight、语言引擎输出、工程诊断和运行时计数，必要时附录屏、DOM 元素或令牌检查结果。公开记录先脱敏，不提交私有工程、完整编译命令中的秘密宏、个人路径、令牌或账号截图。
- 自动测试必须使用隔离用户数据和扩展目录；需要关闭文件、清理测试历史或切换引擎时，不操作用户正在使用的 VS Code 实例。

## 5. 执行命令

### 文档维护

```bash
npm run docs:commands:check
npm run docs:terms:check
npm run docs:prose:check
npm run docs:links:check
npm run release:notes:check
git diff --check
```

只整理测试指导且不改插件行为时，不为此提升正式版本或生成新 VSIX。命令目录没有变化时只检查，不需要重新生成目录。正文保持自然段，不为固定列宽插入换行；代码、列表和表格保留结构。

### 源码修改的基本检查

```bash
npm run check
```

可先编译后运行定向单测，例如预览与导航：

```bash
npm run compile
node --test dist/test/unit/codePreview.test.js dist/test/unit/previewOwnership.test.js dist/test/unit/editorNavigationWiring.test.js
```

### 真实引擎与规模检查

```bash
npm run test:e2e:xvfb
npm run test:e2e:microsoft
npm run benchmark
```

Linux 无桌面环境使用现有 Xvfb 入口；有桌面时也可以运行 `npm run test:e2e`。E2E 启动器默认使用指定版本的独立测试 VS Code，需要已有运行时或网络下载；可用 `C_INSIGHT_VSCODE_EXECUTABLE_PATH` 指定兼容的本地测试程序。Microsoft 用例还需要 cpptools，可用 `C_INSIGHT_CPPTOOLS_EXTENSION_PATH` 指定已安装路径。不要为了运行测试随意修改实际工作窗口的引擎设置。

真实工程只在明确纳入范围时运行：

```bash
C_INSIGHT_FFMPEG_ROOT=/path/to/FFmpeg C_INSIGHT_FFMPEG_CLANGD=/path/to/clangd-20 npm run acceptance:ffmpeg -- /tmp/c-insight-ffmpeg-acceptance.json
C_INSIGHT_FFMPEG_WORKSPACE=/path/to/FFmpeg npm run test:e2e:ffmpeg:microsoft
```

`acceptance:ffmpeg` 是只读协议验收；Microsoft 的真实工程 E2E 应使用启动器创建的隔离测试实例。命令不会替项目生成正确的编译数据库。环境、数据和索引不同，不设置“所有查询必须少于某个固定秒数”这样的跨机器门槛。

发布前还要执行联网的 `npm audit --audit-level=low`。网络失败不等于发现漏洞，也不等于审计通过；不得通过关闭 TLS 校验或忽略错误来完成发布。

依赖跨主版本覆盖需要同时检查兼容性：`dependencyCompatibility.test.ts` 覆盖实际语言客户端的路径匹配、本地化枚举、过期嵌套依赖及构建补丁保护。使用 CI 同版 npm 验证 `npm ci`，重新执行检查与宿主回归，并生成第三方声明；审计为零不能替代接口验证。客户端补丁和适用版本见[开发者手册](../development/developer-guide.zh-CN.md#8-常用开发流程)。

编译参数注入宏的独立场景见[验证说明](command-line-macros.zh-CN.md)。`npm run probe:command-line-macros` 构建并直接查询 clangd，`npm run test:e2e:command-line-macros` 在独立 VS Code 中查询 C Insight；均需要已有 `cc`。宏专项单独运行，覆盖显式查询和受控可见性的自动路径；原生输入/布局按人工清单检查。宏定义、调用者及预览位置分别断言。

## 6. 高频问题人工冒烟清单

修改公共交互时按以下条件检查相关项，正式发布时追加相邻场景。

1. 启动与跨文件：打开 C 文件，分别选择本地函数、跨文件函数、宏和字段；确认预览、引用及可见方向的调用树符合引擎能力，没有竞争服务误用或持续初始化失败。
2. 预览超时：语义着色迟到时，源码仍能在配置等待上限后用词法回退显示，不能只因为定义已返回就宣布预览正常。
3. 显式选择优先：选择符号后立即点它的调用点，再等待迟到详情；代码预览不得弹回原定义，其他窗口可继续完成各自查询。
4. 滚动：新预览首次向上/下滚轮立即生效，长行横向滚动条始终可用；预加载、后续详情及定义升级不闪回初始位置。
5. 预览样式与空白：普通代码没有灰色圆角覆盖层；目标标记仍正确；双击代码、行尾、行号附近及代码区空白都定位到有效行并保留预览。
6. 树操作：单击名称只预览，双击或 Enter 只打开编辑器而不改变展开状态；箭头、左右键只处理分支。双击不立即重刷随光标窗口，主动移到其他位置后才恢复。
7. 原生历史：先在目标文件远处停留并关闭，再从源文件跳入；侧键后退一次直达源位置，前进一次直达目标；已打开文件和同文件跳转同样成立。
8. 固定：引用独立固定、调用者与被调用者共享固定；浏览其他符号不重复查询或重绘固定引用，显式动作仍可执行，源修改允许标记过期，反复固定不累计状态行。
9. 宏：宏别名默认只返回该拼写的直接引用；定义名、数值宏、表达式宏和替换文本均能查询；只有显式按钮才切换到展开后函数。编译参数 `-D` 宏另查 049：clangd 明确识别时调用者保留宏身份及 `#if` 使用，无源码定义的根锚定当前使用；上下文隐藏仍自动跟随。分别生成宏值 `1`、`0` 的数据库，函数调用者只含各自生效分支；函数式宏产生的调用计入目标函数，查询宏自身时保留宏范围。检查准确位置、单次悬停共享、普通函数快速路径及全隐藏零请求。预览单独比较原始定义、展开函数与当前使用的文件/行号，并区分仅悬停与移动编辑器光标。
10. 字段：成员分类关闭时走原始完整结果路径；开启时保留同一变量、其他路径和无法确认三组，不隐藏不确定候选，也不批量打开候选文件。
11. 光标与编辑：空白不清空已有结果；慢速输入前三个字符和持续输入都不触发额外的光标自动语义查询；随后鼠标或方向键主动移动仍能恢复跟随。
12. 可见性与状态：隐藏或折叠窗口不触发其光标查询，独立查询包含/被包含方向；关闭关系图后重开工作区不能恢复它；未关闭的受支持会话状态按配置恢复。
13. 主题与布局：中文/英文、明暗主题、长行、多面板布局及文档符号中心指示正常；不要把主题颜色不同或显示“编辑器中心”当成语义查询失败。固定配色还需检查三种模式、类别覆盖/非法值回退、锁定时热更新不重置滚动和隐藏后应用新配置，详见[配色验收](code-preview-fixed-colors.zh-CN.md)。
14. 配置与交付：在对应 WSL/SSH 或多根环境核对配置写入位置；确认临时包、版本、提交和日志来自同一构建。发布按先主干 CI、后版本 Tag 的顺序执行，并下载正式附件验校验和。
15. 引用分组展开：所有非平铺分组都遵守 `cInsight.references.autoExpandGroups`，默认关闭；运行时切换不额外查询，平铺与手动全部展开/折叠不回归。
16. 工程文件：搜索常驻；未锁定成功打开后清空，离焦时只在筛选隐藏当前文件时清空并定位，视图内搜索/菜单交互不跳动；锁定后保留输入及滚动但高亮继续更新。筛选后打开及切换编辑器标签页时尽量将高亮文件居中，首尾自然限位，同一可见文件的重复更新不反复拉回。自动动作不抢焦点，失败或迟到打开不覆盖新查询。隐藏不扫描、文本编辑不重扫，文件变化合并刷新；另核对多根同名文件、二进制打开、数量提示及稳定锁定按钮。
17. 文档符号搜索：顶部输入常驻，大小写不敏感名称子串命中折叠类/结构体成员并保留父链；“×”和 Escape 清空不隐藏，正常展开记录不被筛选操作覆盖。未锁定时双击、Enter、右键打开成功后清空，重复打开同一符号也适用；单击预览、打开失败和后来输入的新词保持不变。窗口内搜索/列表/菜单交互不跳动，离焦跟随只清空隐藏中心符号的查询，仍命中则保留；按稳定 ID 而不是投影对象判断可见性。锁定暂停自动清空/滚动，但不冻结数据或高亮；解锁按焦点规则恢复，按钮槽位和其他窗口状态不变。关闭中心跟随时，显式打开仍可清空但不展开祖先或滚动。隐藏重显保留搜索状态，位置/名称/类型排序只重排同层且不增加语义查询。真实图标、搜索输入、隐藏重显、排序菜单和滚动仍需人工验收。

18. 组合视图创建：通过命令创建并确认功能多选框，不能只写设置模拟；检查中文/英文按钮和窗格名称。运行时清单标题为 `{ value, original }` 时同样成立，不出现字符串方法异常或 `[object Object]`，非法字段有可读回退。
19. 组合视图主题：对比独立栏目，检查横纵滚动条及其悬停/拖动、代码与界面字体、输入框、菜单、焦点和选中状态；切换深浅/高对比度主题及字体设置后即时生效，预览无灰色圆角覆盖，固定配色不被覆盖，筛选词、展开及滚动不重置。
20. 组合标题排序：同一组合内拖动标题文字插入到目标前后，比例随窗格移动且顺序保存；横纵、折叠窗格及窄区域边缘滚动均适用。取消或外部改布局不写回旧顺序，原位放下不保存，失败恢复宿主布局。拖动不触发查询或重置浏览状态，不影响标题按钮、分隔条及菜单排序；结束后新鼠标移动才恢复悬停。硬件捕获、键盘菜单及重载人工检查。
21. 总工具栏与时间配置：水平组合左侧竖排、垂直组合顶部横排，子窗格标题不变；总工具栏从 Webview 左缘开始，内容充满右侧宽度，没有外层空白，工具栏及子文档内部边距保留。长名称及短/窄区域仍能查看名称、访问全部按钮。检查触发/动画/恢复的默认值、`0`、热更新、等待中改值和减少动态效果；元数据更新不跳过等待，取消后不迟到扩展，配置不重建子文档或增加语义请求。宿主入口另见 `combinedToolbarTiming.ts`。

22. 扩展方向与按钮稳定（CI-REG-053）：各栏目可独立选择双向、向右／下、向左／上或默认，总方向入口移除。默认随未折叠顺序计算：末尾双向，其余向右／下；显式选择在排序后保持。旧统一方向仅读取兼容，首次用户编辑后保存逐栏格式，恢复默认只影响选中栏目，新映射优先。正向固定起点，反向固定末端，只借指定侧余量；混合悬停、末尾／最小尺寸不错误借用或增加滚动，移出统一恢复。动画中进入标题、预览控件、搜索／结果工具栏冻结当前像素并取消等待，返回内容区的新移动才恢复。核对四个总按钮、设置取消／失败、局部热更新、状态保留及零新增查询；实际滚轮、原生菜单、重载和 WSL/SSH 见组合专项。

23. 文档结构（CI-REG-044）：README 按名称列出 15 个独立视图并链接到对应说明；手册的功能视图章只包含这 15 个栏目，组合布局、关系图、会话及共性运行机制分别归类。除文档主标题外，所有章节标题按层级连续编号；更新逻辑位于功能介绍之后。重排后检查目录、README、相关维护文档的跳转，不能只验证目标文件存在；补图前不加入失效图片或占位说明。

24. 组合展开占比（关联 CI-REG-043、053）：子栏目“…”菜单设置 `1–100` 的整数，仅影响当前组合中的该栏目；取消／无效输入不保存，恢复默认不改基础比例。检查横向宽度和纵向高度的可用区域占比、单向后方余量与末尾、双向最小尺寸及小于基础尺寸时不缩小。普通分隔条仍只改基础比例，排序保留归属、移除清理；操作区热更新不移动按钮，返回内容区的新移动才应用，不重建子文档或增加语义查询。硬件指针、原生输入框、重载和 Remote 环境人工检查。

25. 收缩后的高亮可见性（CI-REG-056）：分别在文档符号和工程文件初始小视图跟随中部目标，再连续至少三轮悬停放大、上下滚动到高亮之外并移出组合。展开期间不拉回；每次缩回后若目标在可见区域外，尺寸稳定后只补一次平滑居中，不依赖点击搜索框或恢复窗口，也不能只检查首次收缩或未滚动场景。若仍可见则保持滚动。锁定、关闭跟随、窗口失焦或视图内搜索／菜单时不强制定位；滚轮、新目标／新输入及显式导航停止旧动画，减少动态效果时直接定位。检查动画中间位置、筛选词、分支展开、选择和焦点，同功能的其他显示实例不滚动，语义请求和文件扫描不增加。临时零高度恢复、原生分隔条、真实鼠标及 WSL/SSH 另作现场检查。

预览自身历史、C Insight 导航历史和 VS Code 原生后退/前进是不同系统，必须说明操作的是哪一套。隐藏 C Insight 窗口不要求 clangd 的后台索引完全停止；源码编辑也仍可能触发文档符号重绘、预览局部更新及语言引擎自身同步，不得把它们都当成光标语义查询泄漏。

## 7. 新问题登记模板与维护流程

新条目复制以下结构，编号取当前最大值加一；同一问题继续补证据而不是覆盖最初现象。首次登记不知道的内容写“未知/待确认”，不要编造。

```text
编号：CI-REG-NNN
标题：可搜索的现象描述
首次记录日期 / 来源：用户反馈、日志或可复现提交
环境 / 构建：引擎、VS Code、扩展版本或临时包、Remote、有效配置
性质：插件缺陷 / 外部引擎 / 配置 / 行为约定 / 已知限制
状态：待复现 / 已复现待定位 / 已定位待修复 / 修复待自动验证 / 待用户验收 / 用户已验收 / 已发布 / 已知限制
复现步骤：最小输入、入口、动作顺序、是否冷索引、可见/固定窗口
预期与实际：包括准确位置、次数、顺序或范围，不只写“正常/异常”
证据：脱敏日志、截图/录屏、请求计数、仓库测试或提交
定位：已确认根因；仍待验证的假设；已证伪方向
回归：自动测试路径与断言；必须人工验证的部分
本次执行：命令、日期、构建、实际结果；跳过与原因
验收与发布：用户确认及正式版本；未授权则保持未发布
关联：其他问题编号、相关模块及文档
```

维护顺序为：登记报告 → 最小复现 → 补失败断言或说明无法自动化 → 修复及相邻场景回归 → 临时包与重点测试 → 用户验收 → 按授权发布。外部原因或暂时无法复现时，保留条目和可执行的后续采证步骤，不以“没有结果”直接关闭。

新增条目后检查编号不重复、引用的测试文件真实存在、自动化覆盖表述不过度承诺，必要时把共性场景提升到第 6 节。将运行记录追加为带日期的证据，不篡改旧日志、旧 Release 或历史测量。收到纯功能咨询时可完善相关案例的解释，但不得虚构新缺陷或未经用户要求启动延期功能。
