# 编辑器跳转历史修复验证

记录日期：`2026-10-17`。修复基于 `0.22.23`，用户已确认临时 VSIX 功能正确并授权推送与发布，正式纳入 `0.22.24`。下列自动结果是本次环境中的验证记录，不是对其他机器的性能承诺。

## 复现与原因

在隔离的 VS Code `1.130.0` Extension Host 中，先将目标文件的光标停在第 91 行并关闭，再将源文件光标停在第 38 行。从 C Insight 打开位置命令跳到目标文件第 16 行后，执行 VS Code 原生后退命令，修复前实际返回目标文件第 91 行，而不是源文件第 38 行。

原实现先 `showTextDocument` 恢复目标文件的旧光标，再赋值 `editor.selection` 跳到新目标。两次位置变化会形成多余的原生导航记录。代码预览、源码结果树与关系图均存在相同模式。

## 修复边界

`src/utils/editorNavigation.ts` 在同一次 `showTextDocument` 调用中传入折叠的目标选区；返回后只通过 `revealRange` 调整可见范围，不再次设置光标。结果树的双击和 Enter、打开位置、转到定义、代码预览的双击与打开编辑器动作、关系图均复用该入口。关系图仍打开非预览标签并沿用条件居中，其余入口保留原有预览标签策略。固定、锁定、树展开及双击后的随光标抑制逻辑不变。

生产代码不会清空 VS Code 历史，不接管鼠标按键，也不会删除旧版本已经产生的冗余项。代码预览自己的浏览历史与编辑器原生历史仍相互独立。
