# C Insight 历史问题与回归案例库

汇编日期：`2026-10-17`；当前行为基线：`0.22.24`。本库结合历次用户反馈、[更新日志](../../CHANGELOG.md)、Git 历史及现有测试建立，共 `48` 条初始记录。编号永久保留；后续报告按[测试指南](regression-testing-guide.zh-CN.md)继续登记，不删除已经修复或曾经错误归因的记录。

下面的“覆盖”是当前源码中已核对的测试入口，不代表本次重新执行了所有引擎和人工操作。条目标为已有修复、回归约定或已知限制，与本次构建是否测试通过是两个维度。没有可靠版本或根因证据的早期反馈明确保留未知项。源码行号随项目修订变化，实际复现应按符号定位。

## 一、引擎启动、日志、配置与 Microsoft 兼容

<a id="ci-reg-001"></a>

### CI-REG-001 clangd 启动失败后请求连接被销毁

- 历史现象：早期启动出现 `starting → failed`，随后上下文和文档符号报 `Pending response rejected since connection got disposed`。
- 定位与现状：这是连接失败的后果，不足以确定最初原因；早期这份日志的首要根因未从现有记录完整核定。当前启动参数、版本定位及初始化均有检查，不能把所有同类日志都归因于同一个参数。
- 复现与预期：用有效 clangd 路径启动最小 C/C++ 工程，检查选中的程序、版本、完整启动行和最早错误；成功时进入就绪并完成定义查询，失败时给出可定位的首要错误，不以重复连接错误替代它。
- 覆盖：[参数单测](../../test/unit/clangdArguments.test.ts)、[协议集成](../../test/integration/clangdHandshake.test.ts)和 clangd E2E；实际机器 PATH、权限及系统库仍需环境验证。

<a id="ci-reg-002"></a>

### CI-REG-002 重复注册 clangd.applyFix 导致初始化中断

- 历史现象：出现 `command 'clangd.applyFix' already exists`，语言服务短暂就绪后被关闭，所有功能不可用。
- 定位与现状：多个客户端共享 VS Code 全局命令名。当前自管客户端过滤执行命令注册，保留导航和文档同步；这不表示可以忽略其他提供程序冲突。
- 复现与预期：覆盖命令名已注册的初始化路径；不得因重复注册退出，也不得误移除定义、引用或同步功能。测试冲突需要隔离实例，不在实际工作窗口随意启用第二个引擎。
- 覆盖：[客户端功能过滤单测](../../test/unit/navigationLanguageClient.test.ts)是直接守卫；启动 E2E 验证正常路径，完整双客户端竞争仍需专门环境。

<a id="ci-reg-003"></a>

### CI-REG-003 被调用者协议返回 method not found

- 历史现象：`callHierarchy/outgoingCalls` 返回 `-32601: method not found`，被调用者失败。
- 定位与现状：与所选 clangd 的协议能力相关；项目以 clangd 20 或更新版本提供完整被调用者支持。此项是版本能力边界，不是升级插件就能为旧引擎补出的能力。
- 复现与预期：分别验证支持与不支持的方法路径；支持时最小函数返回被调用者，能力不足时给出明确解释，而不是当成确定的空结果或重复重试。
- 覆盖：[真实 clangd 20 协议集成](../../test/integration/clangdHandshake.test.ts)；旧版本提示需对应引擎环境复核。

<a id="ci-reg-004"></a>

### CI-REG-004 普通 clangd 日志及编译命令被误标为错误

- 历史现象：`I[...]` 请求、预编译头构建以及多行编译命令的目录/续行显示为 `[error]`，被误认为源码编译失败。
- 定位与现状：clangd 的标准错误流并不全是错误；日志分类必须识别前缀并继承多行级别，同时保留真实 `error:` 与 `warning:`。
- 复现与预期：输入普通协议日志、多行编译命令和夹杂的真实诊断；前两者不误报，真实错误不被降级隐藏。可靠性状态应从状态栏和诊断查看，不复制成每个结果窗口的重复通用警告。
- 覆盖：[日志分类](../../test/unit/clangdLog.test.ts)、[状态栏可靠性](../../test/unit/reliabilityStatusPresentation.test.ts)及[诊断模型](../../test/unit/projectDiagnosticsModel.test.ts)；显示样式需人工检查。

<a id="ci-reg-005"></a>

### CI-REG-005 clangd SIGSEGV 后 EPIPE 和已销毁流错误刷屏

- 历史现象：进程 `SIGSEGV` 后，待发送的 `didOpen` 连续报 `write EPIPE`、`Cannot call write after a stream was destroyed`。
- 定位与现状：进程崩溃是首要故障，写管道失败是次生错误。`0.22.7` 加入有界自动恢复与重复传输错误合并，不能宣称插件修复了 clangd 内部崩溃。
- 复现与预期：在受控测试中使引擎异常退出；三分钟窗口内最多四次自动重启，第五次停止并提示人工处理；正常停止不耗费崩溃预算，重连成功后恢复同步和错误计数。
- 覆盖：[恢复策略](../../test/unit/clangdRecovery.test.ts)；完整进程故障注入和现场崩溃输入仍需专门测试，不能在用户工作引擎上直接杀进程复现。

<a id="ci-reg-006"></a>

### CI-REG-006 选择引擎不等于所有 VS Code 提供程序都已隔离

- 历史现象：微软 IntelliSense 已禁用仍有冲突提示；另一种情况是启用多个扩展却没有及时提示，用户以为所有结果严格来自选定引擎。
- 定位与现状：`0.18.19`–`0.18.22` 改为结合有效设置检测、处理扩展激活竞态并去重通知。clangd 核心请求直连自管进程，微软公共提供程序命令不能任意强制指定扩展；预览语义令牌也走公共提供程序。
- 复现与预期：组合两种引擎、扩展存在/激活、`C_Cpp.intelliSenseEngine` 和 `clangd.enable`；已关闭的服务不误报，已知有效竞争不漏报，微软模式不暗启自管 clangd，引擎名称和诊断不误称为另一引擎。
- 覆盖：[冲突模型](../../test/unit/providerConflictModel.test.ts)、[微软提供程序状态](../../test/unit/microsoftProviderStatus.test.ts)、[引擎展示](../../test/unit/enginePresentation.test.ts)及双引擎 E2E；真实激活时序仍需复核。

<a id="ci-reg-007"></a>

### CI-REG-007 禁用冲突服务写错设置范围或覆盖用户后续修改

- 历史现象：WSL/SSH 中操作后本机用户设置改变，或点“在此工作区禁用”却没有有效写入；多根范围不受支持时动作失败。
- 定位与现状：`0.18.19`–`0.18.21` 使用 VS Code 支持的最小工作区范围；单文件夹落入 `.vscode/settings.json`，多根按配置能力落入 `.code-workspace`。恢复前核对当前值，不能覆盖用户之后自行更改的值。
- 复现与预期：在 Local、WSL、SSH 和多根窗口确认提示中的目标与实际文件一致；拒绝操作不写入，写入失败可见，恢复仅撤销自己仍有效的写入。C Insight 不能保证外部 clangd 扩展自己的提示采用同一策略。
- 覆盖：[冲突策略单测](../../test/unit/providerConflictModel.test.ts)；具体配置写入、失败恢复和 Remote 文件落点主要靠对应环境人工验证，不能把模型测试当成这些操作已经全覆盖。

<a id="ci-reg-008"></a>

### CI-REG-008 跨文件头文件找不到或切换平台后语义结果不正确

- 历史现象：FFmpeg `tools/decode_simple.c` 中的项目头文件报找不到；嵌入式多平台宏、sysroot 与生成头文件不一致，用户需要反复 clean 和全量构建。
- 定位与现状：编译数据库存在不代表包含当前翻译单元；引擎各自需要有效配置，微软的 `compileCommands` 不由 C Insight 自动代设。不同平台应保留独立分析配置/构建目录与生成头文件，不把递归 includePath 当成完整编译语义。
- 复现与预期：用带条目与缺条目、两套宏和工具链的夹具对照；诊断可解释当前文件采用的命令，切换分析配置后结果符合活动平台。不能要求同一活动配置同时精确解析所有互斥宏分支。
- 覆盖：[配置与诊断模型](../../test/unit/projectDiagnosticsModel.test.ts)、[可靠性模型](../../test/unit/analysisReliability.test.ts)；实际工具链、sysroot、构建脚本及双平台环境依[专项指南](../user/cross-compilation.zh-CN.md)验证。

<a id="ci-reg-009"></a>

### CI-REG-009 Microsoft 原生调用者展开触发 cpptools 崩溃

- 历史现象：本地函数可用，查询跨文件函数的调用者子节点时 cpptools `SIGSEGV`；VS Code 自带调用层次也能触发。根刷新不一定崩溃，实际展开才是关键入口。
- 定位与现状：崩溃属于外部原生服务；当前微软调用者默认采用引用与文档符号映射的安全回退，并有原生/禁用选项，不能宣称保证 cpptools 永不崩溃。
- 复现与预期：隔离配置后比较根准备、展开和 VS Code 原生入口；默认路径不调用原生传入调用展开，故障后不复用失效缓存，被调用者保持自身提供程序身份与能力。
- 覆盖：[微软调用者回退模型](../../test/unit/microsoftCallerFallback.test.ts)、[Microsoft 主 E2E](../../test/e2e/suite/microsoftEngine.ts)和[FFmpeg E2E](../../test/e2e/suite/ffmpegMicrosoft.ts)；真实崩溃输入应交外部引擎问题追踪，不以一次通过关闭它。

<a id="ci-reg-010"></a>

### CI-REG-010 微软已返回引用但调用者显示 No callers found

- 历史现象：等待很久后显示无调用者，但源码确有跨文件调用，提供程序也返回了引用。
- 定位与现状：`0.18.8` 修复 cpptools 将 C 函数以带签名的平铺 `Interface` 符号返回时的归属识别；暂时空的字段引用也不能永久缓存。没有引用与有引用但无法映射必须分别解释。
- 复现与预期：覆盖嵌套函数归属、平铺 C 函数、真正 Interface、未映射引用和索引暂时空结果；不能把所有 Interface 都当函数，显式刷新应有机会取得更新结果。
- 覆盖：[回退模型与空结果解释](../../test/unit/microsoftCallerFallback.test.ts)、[微软字段与函数 E2E](../../test/e2e/suite/ffmpegMicrosoft.ts)；结果完整性仍受提供程序限制。

## 二、代码预览渲染、异步顺序与滚动

<a id="ci-reg-011"></a>

### CI-REG-011 定义已返回但代码预览长时间不显示

- 历史现象：本地函数有预览，跨文件函数没有；VS Code 转到定义却能成功，最初被误认为定义查询或编译配置失败。
- 定位与现状：`0.18.6` 确认整文档语义令牌迟迟不返回阻塞了渲染，加入默认 1500 ms 等待上限与词法回退。`0.18.7` 移除了经实测证伪的根准备/空结果防御补丁；当前无符号保留另由 036 的策略控制。
- 复现与预期：同时观察定义和着色阶段；让令牌为空、超时或失败，源码仍可预览并导航，不无限等待。超时只界定预览等待，不保证公共命令中已派发的外部工作被真正取消。
- 覆盖：[高亮与转义单测](../../test/unit/codePreview.test.ts)、[真实微软预览回归](../../test/e2e/suite/ffmpegMicrosoft.ts)；慢提供程序场景需保留证据，不靠“最后显示了”判定没有阻塞。

<a id="ci-reg-012"></a>

### CI-REG-012 预览与调用树根停在声明而不是实现

- 历史现象：选择 `av_read_frame` 等跨文件函数时，预览和调用者根定位到头文件声明。
- 定位与现状：`0.22.2` 起比较定义与声明，优先独立实现；只有声明时明确回退，索引完成或有界重试可升级。展示位置改变不能改写提供程序原始不透明调用项。
- 复现与预期：覆盖头文件声明/源文件实现、两种查询返回同一位置、实现暂不可用；实现可用时升级，锁定或用户已在预览交互时不抢占内容，后续调用展开仍使用原始项。
- 覆盖：[定义位置规则](../../test/unit/definitionLocation.test.ts)、[主 E2E](../../test/e2e/suite/index.ts)；不同索引时序需要冷/暖环境检查。

<a id="ci-reg-013"></a>

### CI-REG-013 从预览打开编辑器后预览立即清空

- 历史现象：双击代码或打开当前预览后，编辑器切换事件使预览变回“将光标移动到符号上”。
- 定位与现状：`0.19.5` 增加打开编辑器过渡期间的清除保护；不能用永久保留所有过期内容替代正确的事件保护。
- 复现与预期：双击目标行及无可解析符号的位置，检查编辑器切换前后预览仍保留；过渡结束后的显式清除、锁定和真正的新目标仍遵循各自策略。
- 覆盖：[清除保护](../../test/unit/previewClearGuard.test.ts)、[预览打开宿主动作](../../test/e2e/suite/editorNavigationRegressions.ts)；实际 UI 不闪空需人工复测。

<a id="ci-reg-014"></a>

### CI-REG-014 点选调用点后被迟到的定义预览覆盖

- 历史现象：先选符号，再快速点调用者中的调用点，预览先显示调用点，随后跳回符号定义。
- 定位与现状：`0.22.18` 用 generation 绑定预览所有权，显式树、历史、关系图或预览内动作撤销旧上下文的写权限；仅显示另一个窗口不能夺回它。
- 复现与预期：在迟到详情或定义升级之前选择另一位置，等待旧任务完成；预览保持用户选择，其他窗口仍可完成查询；主动移动编辑器光标或显式刷新才能正常重新取得上下文所有权。
- 覆盖：[所有权模型](../../test/unit/previewOwnership.test.ts)、[调用点时序 E2E](../../test/e2e/suite/index.ts)；慢引擎和快速鼠标操作人工补测。

<a id="ci-reg-015"></a>

### CI-REG-015 长代码没有横向滚动条或必须翻到底才能看到

- 历史现象：长行被截断，横向滚动条仅在全部预览代码底部出现。
- 定位与现状：预览的代码区域应是独立双向滚动容器，横向条位于可见区域底部；这是既定交互，不是自动折行需求。
- 复现与预期：使用超宽代码及多页上下文，在顶部、中部、底部均可横向滚动；增量插入与裁剪后横向位置不丢失，工具栏不被一起滚走。
- 覆盖：[范围与恢复模型](../../test/unit/previewRange.test.ts)只能覆盖部分逻辑；滚动条可见性与不同平台原生滚动条策略必须人工检查。

<a id="ci-reg-016"></a>

### CI-REG-016 第一次滚轮只改变滚动条而不移动代码

- 历史现象：鼠标进入预览后第一下滚轮触发加载，第二下才真正滚动；早期后台准备滚动条又造成整体位置偏移。
- 定位与现状：加载边界不能吞掉用户首次滚轮位移；当前初始缓冲与提前加载优先处理，极端边缘保留受限的待执行位移，不额外恢复错误锚点。
- 复现与预期：目标靠近文件头、中间、尾部时立即向上/下滚动；首次有效手势产生位移，达到真实文件边界则可无位移，不误判为失败，不能出现加载后的双倍滚动。
- 覆盖：[滚轮回放接线](../../test/unit/codePreview.test.ts)、[范围模型](../../test/unit/previewRange.test.ts)；真实滚轮与触控板必须人工补测。

<a id="ci-reg-017"></a>

### CI-REG-017 首次加载上下文明显闪烁或目标初始位置不稳定

- 历史现象：首次向上/下加载闪一下，预览显示后又调整滚动条；希望目标出现在可见区域较靠上的位置。
- 定位与现状：`0.22.21` 在显示前准备受限的上下缓冲，完成 `linesBefore` 锚点定位再显示，靠近边缘提前加载；不能为消除闪烁无界读取整个文件。
- 复现与预期：默认缓冲、禁用增量、超大视窗与文件边界分别验证；新目标一次出现在最终初始位置，上下文按配置定位且受最大加载行数约束。
- 覆盖：[初始缓冲接线](../../test/unit/codePreview.test.ts)、[范围计算](../../test/unit/previewRange.test.ts)；是否可见闪烁、目标高度需人工比较。

<a id="ci-reg-018"></a>

### CI-REG-018 用户已经滚动后又跳回定义初始位置

- 历史现象：定义预览刚显示就滚动，稍后整体刷新又回到最初目标行。
- 定位与现状：`0.22.21` 对相同 URI/范围的重复发布只更新元数据，滚轮与指针交互也取得预览所有权；迟到详情或声明升级不得重建用户正在阅读的内容。
- 复现与预期：预览出现后立即滚动并等待详情，随后展开其他窗口；滚动锚点及横向位置保持。主动换编辑器目标或显式刷新仍可开始新的正常预览。
- 覆盖：[预览接线](../../test/unit/codePreview.test.ts)、[所有权模型](../../test/unit/previewOwnership.test.ts)；真实滚动后的视觉稳定性仍需人工验证。

<a id="ci-reg-019"></a>

### CI-REG-019 所有有代码的位置都像被透明框选中

- 历史现象：几乎每行文字到行尾都有灰色半透明圆角框，不只是目标行的整行高亮；关闭语义着色后颜色消失但框仍存在。
- 定位与现状：DOM 检查确认宿主为每行 `<code>` 应用了预格式背景等样式。`0.22.5` 的多行目标范围假设不是最终根因，`0.22.6` 重置宿主背景、边距、边框、圆角等并恢复准确多行范围。
- 复现与预期：语义开/关、普通行与空白行、单行与多行目标都检查；普通行无灰框，目标标记仍精确，不能通过关语义着色或删掉所有目标标记掩盖问题。
- 覆盖：[源码行样式与高亮单测](../../test/unit/codePreview.test.ts)；实际主题和宿主 CSS 仍需截图/DOM 人工复核。

<a id="ci-reg-020"></a>

### CI-REG-020 预览颜色与编辑器不同或关闭外部扩展后编辑器仍有颜色

- 历史现象：两处函数/成员颜色不同；外部 C/C++、clangd 禁用后，编辑器令牌检查仍显示 `property/classScope`，`Other` 被误解为识别失败。
- 定位与现状：这是当前边界与解释项，不是已实现的编辑器级完全同步。编辑器保留 TextMate 基础着色，C Insight 自管 clangd 也注册语义令牌；预览把类型映射到公开主题颜色变量，不复用完整编辑器主题决议。
- 复现与预期：在 `dc->frame` 等成员上比较令牌检查与预览；区分语义分类、主题回退规则和普通 token 大类。`Other` 不等于语义未知，颜色相同也不等于没用语义；不得宣称当前每个主题逐字符完全一致。
- 覆盖：[高亮分类单测](../../test/unit/codePreview.test.ts)；具体主题、字体和颜色对照主要是人工检查，完整同步尚无承诺。

<a id="ci-reg-021"></a>

### CI-REG-021 预览空白双击不能打开正确源码位置

- 历史现象：只有文字本身能打开，代码区空白、行尾、行号附近双击不响应或落到无效行。
- 定位与现状：`0.19.4` 加入最近已渲染行定位，消息需在宿主验证行号和字符，不能接受浏览器任意提供的文件位置。
- 复现与预期：对有代码、空行、行尾、行号区域及上下空白双击；跳到对应或最近有效行，光标范围合法，预览不因打开编辑器而清空。
- 覆盖：[编辑器导航宿主 E2E](../../test/e2e/suite/editorNavigationRegressions.ts)覆盖有效消息路径；像素到字符换算、真实空白点击与缩放仍需人工验证。

## 三、结果树、导航历史、固定与节点预算

<a id="ci-reg-022"></a>

### CI-REG-022 双击结果同时跳转并展开或折叠分支

- 复现与预期：调用者、被调用者及其他结果树分别覆盖展开/未展开、同名不同节点、快慢连击、Enter/空格/左右键；单击预览、双击打开，展开状态不变，箭头与左右键只处理分支。

### CI-REG-023 双击跳转后所有随光标栏目立即重刷

- 历史现象：用户只是打开结果，刚看的调用树、引用和预览就跟随目标光标刷新。

- 复现与预期：从一个调用点双击打开，等待程序事件结束，再主动移动；第一阶段保持原结果，第二阶段正常跟随，切换另一编辑器也能释放抑制。不能把该规则无差别应用到原本立即跟随的显式入口。
- 覆盖：[跟随抑制模型](../../test/unit/cursorFollowSuppression.test.ts)、[接线守卫](../../test/unit/treeLocationWiring.test.ts)和主 E2E。

### CI-REG-024 侧键后退先停到文件上次关闭位置

- 历史现象：预览或调用者双击跳入文件，后退先到该文件旧光标，第二次才回原位置。
- 定位与现状：`0.22.24` 已通过临时包验收；旧逻辑先打开恢复光标再单独赋值，现改为打开时一次传入目标选区，仅另外调整可见范围。
- 复现与预期：目标文件旧位置远离目标，关闭后从另一文件跳入；一次后退回源、一次前进回目标，多轮稳定；已打开文件与同文件也成立。既有历史不清空，旧冗余项不追溯删除。

<a id="ci-reg-025"></a>

### CI-REG-025 固定引用后仍出现无意义刷新或固定状态串扰

- 历史现象：引用虽仍显示被固定符号，但浏览其他符号时可见重刷；用户也要求调用者/被调用者共享固定，引用与预览独立。
- 定位与现状：`0.19.1` 避免可靠性重算重绘已固定的非空引用；之后状态所有权归各自组件。固定阻止自动替换，不是禁止显式查询或源码变化标记过期。
- 复现与预期：固定引用后点其他编辑器符号和被调用者，比较查询与发布计数而非只看最终文本；调用者任一固定按钮同步另一个，引用与预览不受串扰，手动动作及解锁恢复正常。
- 覆盖：[固定策略](../../test/unit/viewPin.test.ts)、[调用树共享状态](../../test/unit/callHierarchyViewState.test.ts)、[引用接线](../../test/unit/referenceExplorerWiring.test.ts)及双引擎循环；无闪烁与按钮位置需人工检查。

<a id="ci-reg-026"></a>

### CI-REG-026 多次固定/取消固定累积微软调用者提示行

- 历史现象：`Pinned: ...` 在取消固定后变成 `Microsoft Callers: References-based`，最终出现多行同样提示。
- 定位与现状：`0.18.15` 为微软模式行使用独立节点身份，并在重建临时横幅时排除旧行，不能把它当普通固定提示处理。
- 复现与预期：微软模式连续固定/取消三次及更多次，始终只有一个模式提示，没有残留固定行，根节点和已加载结果仍存在。
- 覆盖：[微软真实工程 E2E](../../test/e2e/suite/ffmpegMicrosoft.ts)及调用树状态测试；界面上行数与状态需复核。

<a id="ci-reg-027"></a>

### CI-REG-027 调用树只按函数聚合而无法直接选择每个调用点

- 历史现象与约定：一个函数内多次调用曾藏在额外子层；点击调用者预览其定义，不便直接看实际调用行。此项包含用户交互需求，不全部是协议缺陷。
- 定位与现状：`0.22.0` 平铺调用点，两个 `add`、三个 `main` 显示五行，仅每个语义关系的最早调用点继续展开；`0.22.3` 用被展开符号的独立声明行替代早先多余定义叶子。
- 复现与预期：用 `report` 五个调用点检查行数、排序、准确预览和唯一展开项；调用者与被调用者都保持递归与懒加载。独立声明不是调用边，不重复计入路径、深度、节点预算或导出。
- 覆盖：[调用点投影](../../test/unit/callOccurrenceModel.test.ts)、[定义声明规则](../../test/unit/definitionLocation.test.ts)和主 E2E 的平铺与嵌套声明场景。

<a id="ci-reg-028"></a>

### CI-REG-028 深度输入、节点上限或分类分组造成误解与提前截断

- 历史现象：按深度展开的输入最多填 10，被误解为硬性只能十层；开启成员分类后又出现达到节点上限的疑问。
- 定位与现状：请求展开深度、`maximumDepth` 与 `maximumNodes` 是不同预算。分组、声明等展示节点不能无故消耗语义预算，两方向状态独立；真的达到限制必须明确说明。
- 复现与预期：分别调高合法深度、降低节点预算、构造循环和重复调用点，再开关成员分类；区分深度、节点、递归与取消的停止原因，不能通过无界上限掩盖计数错误，也不硬编码所有场景最多十层。
- 覆盖：[层级预算](../../test/unit/hierarchyTreeState.test.ts)、[展开状态](../../test/unit/hierarchyExpansion.test.ts)、[投影](../../test/unit/callOccurrenceModel.test.ts)；真实分类树与输入框联动仍需人工复验，不据初始日志臆定所有节点上限报告都是缺陷。

<a id="ci-reg-048"></a>

### CI-REG-048 引用分组的自动展开必须可配置且默认关闭

- 历史需求与修订：先要求各引用分类自动展开，随后明确改为提供设置且默认不自动展开；不能按较早需求把所有分组固定展开。
- 定位与现状：`0.22.9` 的 `cInsight.references.autoExpandGroups` 默认为 `false`，应用于文件、目录、函数、引用类型、置信度和证据来源等非平铺模式；切换仅改变展示，不重新发语义查询。
- 复现与预期：各分组分别测试默认值、开、关及运行时切换，再测试平铺、手动全部展开/折叠和已固定引用；平铺保持叶子，设置变化即时作用当前结果，不丢数据、不额外查询。
- 覆盖：[引用分组与默认值守卫](../../test/unit/referenceExplorerWiring.test.ts)、[默认展开与全部折叠树模型](../../test/unit/resultTreeModel.test.ts)；各模式实际层级、固定状态与展示需人工复测。

### CI-REG-029 结构体字段调用者混入其他实例的访问

### CI-REG-030 嵌套成员调用者查询接近二十秒并批量构建 AST

- 复现与预期：对单层、嵌套链及括号基址分别开关分类，比较阶段耗时和请求数；候选复用未保存缓冲区或直接读文件，不能为分类批量打开文档。未识别基址保留未知，不扫描全候选做猜测。

- 复现与预期：同时准备直接函数调用、两个宏别名及嵌套别名；默认只返回所选拼写的直接引用并排除定义，点击展开按钮才改变调用者范围，刷新恢复宏模式；被调用者与关系图不被静默改写。
- 覆盖：[宏身份模型](../../test/unit/macroCallerScopeModel.test.ts)、[仓库接线](../../test/unit/macroCallerRepositoryWiring.test.ts)、[宏行为 E2E](../../test/e2e/suite/macroCallerRegressions.ts)和主 E2E。

### CI-REG-032 在宏定义名上查询没有结果而使用处可用

- 历史现象：宏使用处可列调用者，`#define` 左侧定义名上没有结果。
- 定位与现状：合成的仅用于调用者的宏根使定义处也可查询，展开函数目标留到显式操作时按有界实际使用解析；不能为了按钮预先查询全部目标。
- 复现与预期：同一宏在定义名、普通使用和另一个宏的替换文本分别查询；左侧定义名返回该宏实际使用，右侧符号绑定自己的定义，不混成当前新定义宏；展开目标不可解析时保留已有结果并说明。

### CI-REG-033 数值/表达式宏无结果及未添加文档 AST 错误

- 历史现象：`AVERROR_EOF`、`AVERROR`、`EAGAIN` 等没有调用者，头文件宏出现 `trying to get AST for non-added document`。

- 复现与预期：数值、表达式、替换文本、头文件定义和未打开候选分别测试；未映射引用仍可导航，错误标签不臆称函数外，取消仍应取消，不把部分失败缓存成成功；显式展开目标仅接受可调用项。

<a id="ci-reg-034"></a>

### CI-REG-034 引用分类被误当成精确数据流或调用者结果

- 历史疑问与约定：Read、Write、Read/Write、取地址、宏等分类与调用者混淆；指针、副作用、引用参数、重载及模板来源容易被过度解释。

- 复现与预期：构造读取、赋值、复合赋值、取地址、函数指针及宏参数，切换按类型分组和证据过滤；保留未知与低置信信息，不能把所有引用都叫调用或把未证明的写入标成精确事实。

## 五、自动刷新、资源与会话

<a id="ci-reg-035"></a>

### CI-REG-035 文本编辑尤其慢速输入前两个字符仍触发自动查询

- 历史现象：编辑时调用者、引用等重查，初次优化后慢慢输入的前几个字符仍能触发；不能只检查 selection 事件是否 `Keyboard`。
- 定位与现状：`0.22.17` 以编辑版本与关联选区事件门控，持续到主动离开编辑锚点；单靠短空闲计时无法保护慢速输入。源码同步、过期标记与局部重绘不是同一种查询。
- 复现与预期：新位置上分别慢速输入至少三个字符、快速输入、删除和多次选区事件，再用方向键或鼠标主动离开；编辑不增加光标自动语义周期，主动导航恢复，显式查询仍有效。
- 覆盖：[编辑门控模型](../../test/unit/cursorRefreshModel.test.ts)、主 E2E 的真实输入/计数场景；必须确认字符确实输入编辑器，关联 045。

<a id="ci-reg-036"></a>

### CI-REG-036 光标移到空白或无符号处清空已有结果

- 历史现象：点击无符号位置后各栏目刷新为空，预览提示重新移动到符号。
- 定位与现状：当前自动查询缺少任何符号证据时保留结果；词法空白提前跳过，同一文档版本的已知无符号锚点有界去重。显式清除/刷新与自动保持不是同一规则。
- 复现与预期：选择有效符号后点空格、括号等无语义位置，再回到符号；已有结果不被无意义替换，确定无符号目标不反复重查，真实符号及显式操作正常生效。
- 覆盖：[符号证据](../../test/unit/cursorSymbolEvidence.test.ts)、[光标模型](../../test/unit/cursorRefreshModel.test.ts)和[需求模型](../../test/unit/navigationDemand.test.ts)；多窗口 UI 保留人工补测。

<a id="ci-reg-037"></a>

### CI-REG-037 隐藏窗口仍做光标查询或方向查询带上无关功能

- 历史问题与约定：折叠调用者等窗口是否占资源，以及查询被调用者是否顺带刷新引用；微软模式曾有额外引用查询。
- 定位与现状：按可见需求决定方法，隐藏窗口不调度其光标查询，显式命令只绕过相应可见性门控；`0.18.16` 移除方向刷新中的无关引用。不能要求独立引擎后台索引因此完全停止。
- 复现与预期：全隐藏、只开一个窗口、反复显示/隐藏及仅查单一方向，比较实际请求和调度计数；不读取隐藏树的可见行描述，不因为另一个窗口出现而夺回显式预览。
- 覆盖：[需求不变量](../../test/unit/navigationDemand.test.ts)、[树模型](../../test/unit/resultTreeModel.test.ts)、[微软真实工程资源回归](../../test/e2e/suite/ffmpegMicrosoft.ts)；含默认一层展开的可见方向需一并测试。

<a id="ci-reg-038"></a>

### CI-REG-038 快速移动导致取消队列、缓存或大结果资源累积

- 历史现象：大工程切换过快产生过时请求，取消但尚未执行的项目仍滞留队列；过多引用、导出和缓存可能放大内存。
- 定位与现状：`0.20.1` 清理派发前取消项；调度、合并、前台优先级、引用分页、缓存条目/字节与导出上限都有独立预算。
- 复现与预期：快速切换与大量取消后队列收敛，过时结果不覆盖新目标，缓存及导出不越预算；真实可见数据保留并解释截断/取消，不把限制当成无结果。
- 覆盖：[调度压力](../../test/unit/requestScheduler.test.ts)、[LRU](../../test/unit/lruPromiseCache.test.ts)、[导出预算](../../test/unit/exportBudget.test.ts)、主 E2E 与[性能基线](performance-baseline.zh-CN.md)。

<a id="ci-reg-039"></a>

### CI-REG-039 包含/被包含只显示提示或一次触发两个方向

- 历史现象：窗口只显示针对活动 C/C++ 文件的查询提示，或执行包含文件时连被包含关系也一起扫描。
- 定位与现状：提示可以表示尚未请求，不一定是查询失败；两个方向独立触发，反向查询的扫描成本尤其需要边界。解析器依据可见编译参数，不等同 clangd 内部全部预处理能力。
- 复现与预期：用直接/反向 include、小循环、未解析头文件和生成目录分别单独触发；未请求方向不额外扫描，未知关系可解释，不把未求值的条件分支宣称为活动编译事实。
- 覆盖：[包含模型](../../test/unit/includeModel.test.ts)、[需求模型](../../test/unit/navigationDemand.test.ts)；方向触发、实际文件成本与工具链缺失路径需要工程复验。

<a id="ci-reg-040"></a>

### CI-REG-040 手动关闭的关系图在重开或重载窗口时恢复

- 历史现象：用户已经关闭关系图，重开 VS Code 仍恢复旧窗口和状态。
- 定位与现状：明确关闭与扩展退出必须区分；用户关闭清除待恢复图状态，只有关闭 VS Code 时仍打开的图才按配置保存静态快照。
- 复现与预期：分别手动关图后重载、保留图直接退出、关闭恢复设置，以及缺失源码节点；只恢复应保留的图，不偷偷启动无界语义查询，缺失路径有提示。
- 覆盖：[图会话生命周期](../../test/unit/graphSessionLifecycle.test.ts)、[会话模型](../../test/unit/workspaceSession.test.ts)与[关系图模型](../../test/unit/relationshipGraph.test.ts)；窗口实际关闭/重载人工验证。

<a id="ci-reg-041"></a>

### CI-REG-041 工作区恢复、引擎切换与不支持的树状态混淆

- 历史疑问与约定：按文件夹打开是否算工作区、调用树逐节点是否能恢复，以及切换引擎后旧状态是否仍可用。
- 定位与现状：文件夹工作区也有工作区状态；受支持调用树用稳定路径重查，不序列化提供程序不透明数据；引擎相关状态不跨引擎错误复用。类型/包含树恢复仍是延期项，不判作已实现功能故障。
- 复现与预期：单文件夹与多根分别重载，检查支持的历史、固定与调用路径；切换引擎和损坏/过大会话能安全降级，不恢复已关闭图，不触发不受支持的启动扫描。
- 覆盖：[会话稳定路径、兼容与大小](../../test/unit/workspaceSession.test.ts)、[旧格式兼容](../../test/unit/secondPhaseCompatibility.test.ts)及[图关闭生命周期](../../test/unit/graphSessionLifecycle.test.ts)；这些模型断言不等于已经验证逐节点重查，真实恢复和文件夹切换仍需人工补测。

## 六、文档符号、布局、文档质量与交付

<a id="ci-reg-042"></a>

### CI-REG-042 文档符号图标、中心指示与焦点行为不一致

- 历史需求与疑问：希望像大纲一样区分符号图标，并提示编辑器中心所处符号；“视口中心”名称已改为“编辑器中心/Editor center”。
- 定位与现状：图标形状按符号类型，颜色由主题决定；中心跟随只使用已加载符号，不增加语义查询。文档符号永久模糊搜索框的提案暂未实施，不能误记为现有功能。
- 复现与预期：滚动编辑器而不移动光标，选取包含中心行的最深符号，跨空白/范围边界与隐藏窗口测试；不抢编辑器焦点、不改用户树选择，不发额外符号查询；单击/双击遵循当前统一策略而非早期直接打开行为。
- 覆盖：[符号展示](../../test/unit/symbolPresentation.test.ts)、[中心规则](../../test/unit/documentSymbolFocusModel.test.ts)、[中心接线](../../test/unit/documentSymbolFocusWiring.test.ts)；实际高亮、主题和焦点人工检查。

<a id="ci-reg-043"></a>

### CI-REG-043 工具栏文字过长、固定按钮跳位或底部窗口不能并列归组

- 历史现象与约定：刷新显示整行文字、预览固定按钮脱离原工具栏、上下文固定后按钮位置变化；自绘树后拖放难以把调用者/被调用者放进同一底部容器。
- 定位与现状：主要动作使用主题图标，预览内保留自己的按钮布局；自绘仅替换内容，原生容器仍负责移动。拖放困难可用 VS Code 移动视图命令，不为此重绘全部外层布局。
- 复现与预期：窄面板、固定/取消、多个结果视图、中文/英文及移动到已有底部 C Insight 容器；图标可见并有说明，按钮不因状态改变跳位，同一容器能容纳多个窗口。
- 覆盖：[标题图标守卫](../../test/unit/viewTitleIcons.test.ts)、[自绘树脚本](../../test/unit/resultTreeClient.test.ts)；真实拖放、按钮常显与布局恢复必须人工检查。

<a id="ci-reg-044"></a>

### CI-REG-044 文档出现意外换行、失效链接或中文 UI 与手册不一致

- 历史现象：文档被固定列宽硬换行、重组目录后链接失效、新功能与配置没写入手册，中文模式仍大量显示未本地化名称。
- 定位与现状：已有自然段规范化、本地链接、语言目录、命令/配置/视图完整性及术语质量门；中文在每章节首次出现概念时附英文，源码标识和协议错误保持原文。
- 复现与预期：新增/移动文档、配置、命令或用户字符串后运行相应检查；不能格式化坏代码/表格，也不能把历史发布说明中的旧行为自动改写为当前事实。
- 覆盖：[文档完整性](../../test/unit/documentationCompleteness.test.ts)、[本地化](../../test/unit/localizationManifest.test.ts)、`docs:commands:check`、`docs:terms:check`、`docs:prose:check` 和 `docs:links:check`；语义准确性仍需阅读。

<a id="ci-reg-045"></a>

### CI-REG-045 自动测试因焦点、冷索引或 C 夹具参数误报

- 历史现象：本机通过、GitHub 冒烟失败；编辑计数为零却可能根本没输入字符；新机器调用点暂时不全，C 文件沿用 C++17 参数也会产生错误。
- 定位与现状：输入前立即聚焦且核对实际文本，不能只在异步等待前聚焦；冷索引只做有界重查并报告实际结果；C/C++ 夹具按语言使用真实有效参数；启动器隔离用户目录和扩展目录。
- 复现与预期：让 Webview 延迟获得焦点、使用空索引缓存、同时打开实际 VS Code，确认测试不会误操作工作实例；必须真正在目标编辑器写入字符后才检查查询抑制，不通过放松断言掩盖失败。
- 覆盖：[主 E2E 的真实输入](../../test/e2e/suite/index.ts)、[启动参数](../../test/e2e/testLaunchArgs.ts)、[夹具配置](../../test/fixtures/basic-cpp/.clangd)、[cpptools 发现](../../test/unit/cpptoolsExtensionPath.test.ts)及 GitHub CI；新机器环境问题保留日志定位。

<a id="ci-reg-046"></a>

### CI-REG-046 未等 CI、版本不一致或发布附件不完整

- 历史问题与约定：发布曾受冒烟失败、版本/打包身份、依赖审计及上传方式影响；用户要求新改动先临时包、验收后再正式版本和发布。
- 定位与现状：必须区分本地打包、推送主干、Tag、GitHub Release 与商城发布。Release 流水线验证标签及双语说明，创建 VSIX 与校验和；Marketplace 不是现有 GitHub Release 的自动结果。
- 复现与预期：未验收不发布，先主干对应提交 CI 成功再推注释 Tag；下载正式 VSIX 和 `SHA256SUMS` 验证，检查正文与仓库说明一致、包内版本/发布者/代码正确。网络审计失败不能当通过，不能覆盖旧发布来隐藏失败。
- 覆盖：[发布说明契约](../../test/unit/releaseNotesContract.test.ts)、[仓库身份与包装契约](../../test/unit/publicRepositoryContract.test.ts)、[CI](../../.github/workflows/ci.yml)及[Release 工作流](../../.github/workflows/release.yml)；公开附件与商城状态另行核验。

<a id="ci-reg-047"></a>

### CI-REG-047 公开源码、历史或演示媒体泄漏个人信息

- 历史关注与约定：公开前曾调整提交身份、发布者、历史路径和 README 录屏头像；只改当前文件不能证明旧 Tag 或旧附件不含旧信息。
- 定位与现状：这是发布隐私维护边界，不在本库声称发现了新的漏洞。当前公开身份为 `H9elix`，使用既定 GitHub noreply 邮箱，机器路径及工作数据应脱敏，图标候选和原始录屏不入 VSIX。
- 复现与预期：公开前复核当前包、演示图、作者、Tag/历史和旧附件；不把令牌、私有源码和未脱敏日志写进案例库。不擅自改写或删除历史，应另获明确授权；仅保留本地备份不代表可公开它。
- 覆盖：[公开仓库契约](../../test/unit/publicRepositoryContract.test.ts)可检查当前元数据与包白名单；Git 全历史、图片头像和旧 Release 附件仍需专门人工/工具审计，不能据此宣称全历史已自动证明无隐私信息。
