## 自动覆盖

- [纯模型测试](../../test/unit/projectFileModel.test.ts)：自然排序、路径/类型、同名多根、配置边界、Git 元数据和二进制资源判断；另有无分析引擎/无文本内容订阅的静态接线检查。
- [自动跟随模型](../../test/unit/projectFileFollowModel.test.ts)：视图/应用焦点、可见性、菜单与打开过程、独立锁定、目标缺失和跟随配置的决策；明确打开成功清空与普通离焦条件清空的区别。
- [浏览器事件测试](../../test/unit/resultTreeClient.test.ts)：执行共享 Webview 实际脚本，检查一万行虚拟列表、实时名称/路径过滤、清空、无结果、Escape、活动行补丁、整个视图焦点、自动清空不抢焦点、条件清空、锁定时保留输入/滚动，以及迟到打开不能清掉新输入。普通结果树仍保留原有的定位清空筛选策略。该小型 DOM 环境不是原生浏览器视觉验收。
- [隔离扩展宿主测试](../../test/e2e/suite/projectFiles.ts)：真实 VS Code 多根文件枚举、`files.exclude`、不隐式套用 Git/搜索排除、同名文件、自然排序、活动文本与图片编辑器、关闭跟随、文本编辑/排序不重扫、创建/重命名/删除、隐藏不扫描及再次显示核对、文本预览/打开、二进制回退与数量上限。另暂缓真实文件枚举的结果交付，确认实际控制器取消旧代、扫描串行并拒绝过期结果；这是受控异步交付，不声称模拟了全部远程文件系统时序。
- [焦点和打开宿主检查](../../test/e2e/suite/projectFilesFollowing.ts)：通过真实视图/编辑器焦点切换检查请求门控、焦点在列表时只更新高亮、离开后定位同一文件、独立锁定与解锁、重复打开同一文件、右键打开及失败保持；受控延迟文件状态返回，确认新打开或新预览撤销旧打开的等待状态，不让旧请求卡住后续跟随。宿主断言核对自动清空/定位消息策略，具体输入框和像素滚动效果由浏览器脚本测试与人工 UI 分别覆盖，不把宿主消息发送等同于完整 UI 验收。

入口：

```bash
npm run check
C_INSIGHT_VSCODE_EXECUTABLE_PATH=/path/to/test-vscode/code npm run test:e2e:project-files
C_INSIGHT_VSCODE_EXECUTABLE_PATH=/path/to/test-vscode/code npm run test:e2e:xvfb
```

测试启动器在系统临时目录生成多根工程，测试退出后删除工程，不修改维护者当前打开的工程或设置。图片夹具复用仓库已提交的 PNG，并以大于 10 MiB 的稀疏文件验证尺寸保护不打开文本缓冲区；图片断言核对默认资源编辑器与文件 URI，不替代视觉验收。文件清单测试不要求编译数据库；扩展本身仍可按既有生命周期启动已配置的分析引擎，不能把“枚举不发起语义查询”解释为“引擎进程完全不存在”。显式 C/C++ 文本预览可按既有逻辑同步文档或进行着色。

## 人工重点

1. 安装临时包并重新加载窗口，在 C Insight 中展开工程文件；确认顶部搜索框和“×”按钮、状态行、排序/刷新图标正常。搜索框不能随长列表滚出。
2. 输入文件名、大小写变体及 `src/main.c` 类相对路径，检查实时子串过滤；不存在的内容显示空提示。点击“×”后焦点仍在输入框，完整已加载清单恢复。
3. 未锁定时在搜索框/列表/菜单内操作，输入保留且不自动滚动；离开视图后，当前文件匹配筛选则保留输入，不匹配时清空并定位。自动清空不能把焦点拉回输入框。排除、工程外或未加载的文件不触发清空。
4. 反复锁定/解锁，核对按钮位置稳定，锁定时切换活动文件仍更新高亮但不清空或滚动，手动“×”和滚动仍可用。解锁在视图外同步一次，在视图内等待离焦；关闭跟随配置则不显示高亮、不自动定位。
5. 单击只预览，双击/Enter/右键成功打开后，未锁定时清空并定位，锁定时保留；重复打开同一文件也成立。失败不清空；打开期间输入新查询，不得被迟到结果覆盖。另核对一次原生后退及图片/大文件默认打开方式。
6. 隐藏窗口后创建/删除文件，再显示核对；持续文本输入不反复扫描。大型工程在枚举时快速隐藏、改变排除规则，旧结果不得覆盖新清单。
7. 在 WSL/SSH、明暗主题及底部面板布局中重复相关操作；窗口仍能拖动、归组和调整大小。文件监听被 VS Code 排除或外部批量操作没有及时反映时，手动刷新核对。

## 2026-11-10 交互调整

用户明确要求成功打开后清空、焦点在工程文件外时自动定位，以及独立锁定。随后选择“普通离焦仅在筛选遮挡目标时清空”和“锁定仍跟随高亮”。这是对上一构建交互约定的调整，不把原来按计划保留输入的行为写成缺陷；旧包和上面的带日期验证记录仍保留。

当前实现增加可选的完整 Webview 焦点/输入修订号通知，自动操作使用宿主节点 ID，不接受任意文件路径。高亮与自动定位分开，后者按事件合并并复核最新状态；成功打开、普通离焦和手动清空使用不同策略。新增锁定/解锁命令只影响此视图，按钮位置一致，默认未锁定，锁定不持久化且不修改 `followActiveEditor`。隐藏视图和整个应用失焦时暂缓动作；排序选择框期间不自动跟随。迟到打开携带原输入修订号，浏览器拒绝它及其同目标普通跟随回退。

本轮 `npm run check`、新增模型/浏览器检查、真实宿主焦点/锁定/异步打开专项，以及原有 clangd 主扩展宿主回归均通过。主回归仍包含预览配色、其他结果树和原生后退/前进检查；浏览器用例单独确认自动清空不聚焦输入框、锁定期间手动清空可用，以及旧打开及其同目标回退不能清掉新查询。第一次启动宿主的自动权限审核超时，一次重试后正常完成，不把审核超时记为产品故障。原生搜索框像素滚动、标题栏按钮点击、排序菜单、明暗主题及 WSL/SSH 仍需人工验收，未单独重跑 Microsoft 引擎实机。
