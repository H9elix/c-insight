- [隔离扩展宿主测试](../../test/e2e/suite/projectFiles.ts)：真实 VS Code 多根文件枚举、`files.exclude`、不隐式套用 Git/搜索排除、同名文件、自然排序、活动文本与图片编辑器、关闭跟随、文本编辑/排序不重扫、创建/重命名/删除、隐藏不扫描及再次显示核对、文本预览/打开、二进制回退与数量上限。受控延迟枚举结果验证取消、串行和过期结果保护。

入口：

```bash
npm run check
C_INSIGHT_VSCODE_EXECUTABLE_PATH=/path/to/test-vscode/code npm run test:e2e:project-files
C_INSIGHT_VSCODE_EXECUTABLE_PATH=/path/to/test-vscode/code npm run test:e2e:xvfb
```

测试启动器在系统临时目录生成多根工程，退出后删除工程，不修改当前工作实例。图片夹具复用仓库已提交的 PNG，大于 10 MiB 的稀疏文件用于验证尺寸保护。清单测试不要求编译数据库；显式 C/C++ 文本预览仍使用现有文档同步和着色路径。

## 人工重点

1. 安装待测包并重新加载窗口，在 C Insight 中展开工程文件；确认顶部搜索框和“×”按钮、状态行、排序/刷新图标正常。搜索框不能随长列表滚出。
2. 输入文件名、大小写变体及 `src/main.c` 类相对路径，检查实时子串过滤；不存在的内容显示空提示。点击“×”后焦点仍在输入框，完整已加载清单恢复。
3. 未锁定时在搜索框/列表/菜单内操作，输入保留且不自动滚动；离开视图后，当前文件匹配筛选则保留输入，不匹配时清空并尽量居中定位。直接切换编辑器标签页也应居中，已经可见的新目标同样适用；首尾或不足一屏时自然限位，不增加空白行。自动清空不能把焦点拉回输入框。排除、工程外或未加载的文件不触发清空。
4. 反复锁定/解锁，核对按钮位置稳定，锁定时切换活动文件仍更新高亮但不清空或滚动，手动“×”和滚动仍可用。解锁在视图外同步一次，在视图内等待离焦；关闭跟随配置则不显示高亮、不自动定位。
5. 单击只预览，双击/Enter/右键成功打开后，未锁定时清空并居中定位，锁定时保留；重复打开同一文件也成立。同一可见文件的重复状态更新不得拉回手动滚动位置，再次进入并离开列表则可重新居中。失败不清空；打开期间输入新查询，不得被迟到结果覆盖。另核对一次原生后退及图片/大文件默认打开方式。
6. 隐藏窗口后创建/删除文件，再显示核对；持续文本输入不反复扫描。大型工程在枚举时快速隐藏、改变排除规则，旧结果不得覆盖新清单。
7. 在 WSL/SSH、明暗主题及底部面板布局中重复相关操作；窗口仍能拖动、归组和调整大小。文件监听被 VS Code 排除或外部批量操作没有及时反映时，手动刷新核对。
