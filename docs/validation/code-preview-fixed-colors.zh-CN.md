# 代码预览固定配色使用与验证

## 范围与交付状态

本功能最初在 `experiment/code-preview-fixed-colors` 分支基于 `0.22.24` 实现。用户已确认临时包验证通过，并授权合回 `main`、更新文档、推送和发布，正式纳入 `0.22.25`。本记录沿用 [CI-REG-020](historical-issues.zh-CN.md#ci-reg-020) 的配色边界，并联动检查 011 的语义超时回退、019 的源码灰框和 016–018 的滚动稳定性。

目标是让代码预览（Code Preview）拥有稳定、可配置的颜色，而非完整复制编辑器的 TextMate/语义主题决议。语义类别仍来自当前注册的文档语义令牌提供程序；超时、失败或关闭语义着色时仍使用既有词法回退。不增加额外引擎请求，不做完整词法分析，不补充引擎未提供的语义证据。

## 配置与示例

| 配置 | 默认值 | 可用值与行为 |
| --- | --- | --- |
| `cInsight.codePreview.colorScheme` | `"theme"` | `"theme"` 使用原有公开主题变量映射；`"fixed-dark"` 固定深色；`"fixed-light"` 固定浅色 |
| `cInsight.codePreview.tokenColors` | `{}` | 以下类别到不透明六位十六进制颜色 `#RRGGBB` 的对象；覆盖所选预设中的指定类别 |

将下面的自定义示例合并到现有工作区 `.vscode/settings.json`，不要覆盖其他设置。示例只修改六个类别，未列出的类别保留当前预设：

```json
{
  "cInsight.codePreview.colorScheme": "fixed-dark",
  "cInsight.codePreview.tokenColors": {
    "function": "#FFD866",
    "method": "#FFD866",
    "variable": "#D4D4D4",
    "property": "#78DCE8",
    "macro": "#AB9DF2",
    "comment": "#808080"
  }
}
```

要恢复所选固定预设，将 `cInsight.codePreview.tokenColors` 设为 `{}`；要恢复主题映射，再将 `cInsight.codePreview.colorScheme` 改为 `theme`。

支持的类别及固定模式默认值如下。每个键独立，不存在 `type` 到 `class` 或 `function` 到 `method` 的隐式继承；没有被当前引擎使用的类别不会凭空着色。语义令牌优先于词法回退，同一类别的颜色在两条路径中共享。

| 类别键 | 中文含义 | 固定深色 | 固定浅色 |
| --- | --- | --- | --- |
| `namespace` | 命名空间 | `#4EC9B0` | `#267F99` |
| `type` | 类型 | `#4EC9B0` | `#267F99` |
| `class` | 类 | `#4EC9B0` | `#267F99` |
| `struct` | 结构体 | `#4EC9B0` | `#267F99` |
| `interface` | 接口 | `#4EC9B0` | `#267F99` |
| `enum` | 枚举 | `#4EC9B0` | `#267F99` |
| `typeParameter` | 类型参数 | `#4EC9B0` | `#267F99` |
| `function` | 函数 | `#DCDCAA` | `#795E26` |
| `method` | 方法 | `#DCDCAA` | `#795E26` |
| `variable` | 变量 | `#9CDCFE` | `#001080` |
| `parameter` | 参数 | `#9CDCFE` | `#001080` |
| `property` | 成员 | `#9CDCFE` | `#001080` |
| `enumMember` | 枚举项 | `#B5CEA8` | `#098658` |
| `event` | 事件 | `#9CDCFE` | `#001080` |
| `macro` | 宏 | `#C586C0` | `#AF00DB` |
| `label` | 标签 | `#C8C8C8` | `#000000` |
| `decorator` | 装饰器 | `#DCDCAA` | `#795E26` |
| `keyword` | 关键字 | `#C586C0` | `#0000FF` |
| `string` | 字符串 | `#CE9178` | `#A31515` |
| `comment` | 注释 | `#6A9955` | `#008000` |
| `number` | 数字 | `#B5CEA8` | `#098658` |
| `operator` | 运算符 | `#D4D4D4` | `#000000` |

源码区域的完整默认值如下；这些不是 `tokenColors` 的可配置类别键：

| 源码区域元素 | 固定深色 | 固定浅色 |
| --- | --- | --- |
| 源码背景 | `#1E1E1E` | `#FFFFFF` |
| 普通文字／未分类标识符 | `#D4D4D4` | `#000000` |
| 行号 | `#858585` | `#6E7681` |
| 目标行背景 | `#264F78` | `#DCEBFA` |
| 目标行左边线 | `#007ACC` | `#007ACC` |
| 目标符号背景 | `#5B4B18` | `#FFF2B2` |
| 目标符号轮廓 | `#D7BA7D` | `#B89500` |

标题、工具栏、原生滚动条和操作系统的文本选中样式不在固定源码配色范围内。参数/只读斜体及弃用删除线沿用现有规则；不新增逐类别字体或背景自定义。

只接受以上类别键和 `#RRGGBB` 字符串。`#FFF`、含透明度的八位颜色、颜色名、CSS 变量、非字符串及未知类别均不接受。设置界面提供结构校验；运行时仍独立验证，非法项回退到所选预设的该类别颜色，保留其他有效项，并显示去重警告。未知键只在提示中概括为 `unknown token`，不会执行或回显任意 CSS 值。移除覆盖键或设回 `{}` 即恢复所选预设；错误的配色模式值回退到 `theme`。

## 更新与性能边界

切换上述两个配色项或 VS Code 主题只更新独立样式元素。不替换源码 HTML、不重新解码或请求语义令牌、不清理语义与滚动缓存、不改变目标、锁定或历史、不主动设置滚动位置。隐藏窗口跳过样式消息，重新显示或 Webview 准备完成时读取最新设置。其他内容配置及源码编辑仍遵循原有刷新规则。

本方案不消除原有语义请求耗时，默认 1500 ms 超时回退仍有效；也不承诺改善首次引擎查询性能。深浅预设不自动随编辑器主题切换，用户自定义颜色的对比度由用户自行选择。公共提供程序可能返回不同类别，不能把颜色差异直接解释为分类错误。

## 自动检查范围

- `test/unit/previewColors.test.ts`：预设、全部类别、独立覆盖、非法输入、CSS 注入拒绝、共享默认值保护、配置清单、源码样式重置及实际浏览器消息分支；消息分支以受控 DOM 在 JavaScript 虚拟机中执行，不等同于真实浏览器截图测试。
- `test/unit/codePreview.test.ts`：既有源码高亮、目标范围、宿主样式重置、初始缓冲和滚动更新接线。
- `test/e2e/suite/previewColorRegressions.ts`：在真实 VS Code 扩展宿主中读取和修改隔离配置，以受控 Webview 验证初次预设、自定义/重置、热更新、隐藏与就绪同步、锁定、状态和缓存保留；不会把受控消息收发误称为真实物理滚轮验证。由 clangd 与 Microsoft 两套主回归共同执行。

## 持续人工回归重点

1. 安装本次临时 VSIX，在函数、参数、成员、类型、宏、注释、字符串及数字附近打开预览。依次测试 `theme`、`fixed-dark`、`fixed-light`；固定预设的文字与背景应可读，默认主题模式不回归。
2. 自定义 `function`、`method`、`property` 和 `comment`，确认各自生效；删除一个键，确认该类别回到当前预设，不连带修改其他类别。输入无效颜色应提示并回退，不破坏其他有效颜色。
3. 在明暗 VS Code 主题之间切换，固定模式的源码配色保持不变，标题和工具栏继续跟随主题；切回 `theme` 后恢复主题变量配色。
4. 锁定预览，滚到远离目标的位置并横向滚动，再切换配色。源码不闪空、不回到目标、不改变锁定。隐藏窗口后改配置，重新显示时应使用新配置。
5. 关闭 `cInsight.codePreview.semanticHighlighting`，确认词法颜色仍使用所选预设；恢复后确认分类、导航和默认超时回退仍有效。未被词法识别的标识符显示普通文字色是预期限制。
6. 检查普通代码与空白行没有逐行灰色圆角覆盖层，目标行和目标符号仍可辨认；首次上下滚动、增量加载、单击预览内定义和双击打开编辑器不回归。
7. 在实际使用的分析引擎中完成上述验收；双引擎的自动宿主通过不代表私有工程、全部主题或全部 Remote 环境已经手工通过。

用户验收仅对应本次临时包及其实际测试范围。后续修改继续先交付临时包、确认后再发布；完整编辑器主题同步仍不在本次范围内。
