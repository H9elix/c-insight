# 视图入口与菜单验证

## 功能契约

“C Insight：打开视图…”列出 15 个独立视图、最多四个启用组合、创建及管理入口。独立视图执行自己的原生聚焦命令，组合执行对应槽位的聚焦命令；确认前重查组合仍启用。无组合时管理入口提供明确的创建选择，槽位用满时沿用现有提示。浏览和取消列表不打开栏目、改写配置或请求语义分析。

首次提示由原生栏目的真实可见性触发，覆盖无查询的导航历史／书签及恢复出的已启用组合。命令未注册时先记住可见事件，完成注册后再提示。多个同时可见栏目合并为一次，关闭通知也持久记忆；存储失败记录输出并避免会话内循环提示。释放后不再显示待完成通知或响应其按钮。

编辑器菜单使用独立的 `0_navigation_cInsight` 分组，排序在 clangd 的 `0_navigation` 分组之后，由 VS Code 在分组边界显示原生分隔线。clangd `0.6.0` 的 `Switch Between Source/Header` 位于前一组的序号 `5`，C Insight 七个顶层入口在自己的组内依次占用 `1–7`，内部不另加分隔线。只修改 C Insight 的菜单 contribution，不移动或复制外部命令；未安装 clangd 扩展时仍显示 C Insight 自身入口，不以此启动额外分析引擎。

## 自动入口

- `viewCatalog.test.ts`：15 个视图的顺序、用途、英文别名、本地化对象、零至四个组合、重复名称和管理入口，关联 CI-REG-050。
- `viewDiscovery.test.ts`：直接执行生产服务，覆盖解析参数／取消令牌／返回值、实际可见性、注册时序、提示持久化与隔离、存储失败、释放、无副作用取消及所有选择分支。
- `viewMenu.test.ts`：源码／头文件切换之后的独立分组、七个顶层入口、六个子菜单动作、语言条件、默认快捷键和本地化的手册菜单路径，关联 CI-REG-043、044；声明检查覆盖组边界及顺序，真实桌面位置和分隔线仍需人工确认。
- `suite/viewDiscovery.ts`：组合宿主中的原生选择框，用原生候选选择命令打开和取消；检查 19 个原生注册、浏览取消的可见性／请求计数不变、独立调用者不被重定向到组合、指定槽位聚焦及无查询栏目提示观察。

宿主使用隔离用户数据和扩展目录，不操作日常 VS Code。原生 `type` 命令不能作为选择框文本输入的可靠模拟，因此实际键入筛选列为人工检查，不用候选选择测试代替搜索效果验收。

## 重点人工检查

1. 在命令面板和 C/C++ 编辑器右键打开列表；分别输入中文名、英文名、用途，确认实时匹配、取消无动作，选择独立栏目后打开目标而非组合。
2. 查看编辑器右键顺序：clangd 的 Switch Between Source/Header 下方先显示原生分隔线，再依次为打开视图、为当前符号添加书签、两种包含关系、两种关系图、符号导航；C Insight 的七项内部不插入分隔线。C++ 显示类型导航，C 不显示。clangd 扩展未安装时仍有 C Insight 入口。命令面板、快捷键、栏目按钮和结果右键动作不变。
3. 首次打开任一栏目看到非模态提示；关闭后重载不重复。只激活扩展、打开源码或选择框不触发。恢复栏目、先打开导航历史／书签也能触发。在新的测试配置文件或 Remote 扩展宿主验证独立记忆，不清理日常全局状态。
4. 用零个、重复名称及四个组合检查打开、创建／管理；选择框打开期间关闭目标组合，不应重新创建它。打开栏目后的实际加载遵守原有可见性和引擎规则。
5. 在简体中文语言包、WSL／SSH 及原有底部归组布局检查文本、菜单和栏目位置；确认没有自动重新排版。
